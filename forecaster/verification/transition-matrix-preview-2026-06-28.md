## ⚠️ このプレビューの位置づけと限界（先に読むこと）

このドキュメントは提案レポート（forecast-accuracy-improvement-proposal.md）の **M7（ATT&CK遷移エンジン）を第2段階で本格運用する前の試算**である。以下の理由により、**遷移確率の確定値・確度=高の根拠には一切使用してはならない**:

1. **2週分・統計的に無意味**: 後続遷移を持つ観測は from別で initial-access 20件 / persistence 10件 / execution 6件のみ。他は n<3 で完全に無意味。90日（提案の目標）には程遠い。
2. **時系列遷移ではなく共起＋キルチェーン順の推定**: observations には技術間のタイムスタンプが無い。本試算は「1観測（=1インテリジェンス報告）内に共起した tactic を ATT&CK 慣習順に並べ、隣接ペアを遷移とみなした」もの。**実際に時間順で観測された遷移ではない**（提案レポート M7 保留理由1の通り）。
3. **脆弱性インテリ偏り**: 本観測はCVE/APTインテリ報告であり、攻撃の全キルチェーンを追跡したものではない。「実悪用確認＋永続化（Webシェル）」が報告されやすく、execution/discovery 等の中間段階は報告に現れにくい。これが下記 initial-access→execution の乖離の主因。
4. **閉ループ採点バイアス**: 同一系統が予報執筆と観測正規化を行う構造的バイアス（提案レポート M7 保留理由2）。本格運用時はタイムスタンプ順序固定・役割分離・unverifiable率監視が必須。

→ 結論: **本プレビューは「形が出始めたか」を確認する診断であって、較正そのものではない。** knowledge/ への反映は90日蓄積後に Issue/PR で人間レビューを経ること（行動原則5）。

## 集計方法

- 各観測の techniques から distinct tactic 集合を取り、ATT&CK キルチェーン順（reconnaissance→…→impact）にソート。
- 隣接する tactic ペアを「遷移」として1カウント。
- 観測確率 ≈ その隣接遷移カウント / その from-tactic が後続を持つ観測数。

総観測85 / 多tactic観測（チェーン化可能）31 / 観測遷移ペア種類21 / 総遷移カウント42。

## 暫定的に見えてきたこと（仮説・確定ではない）

1. **initial-access→persistence が実データでも支配的**（種0.60に対し観測0.50・10件）。これは堅い。Webシェル展開（T1190→T1505.003）の繰り返しが効いている。M7本運用時、この遷移は早期に較正できる候補。
2. **種にない新規遷移が複数出現**: persistence→{collection, defense-evasion, C2}、initial-access→credential-access、execution→C2 等。90日後の較正で種マトリクスに追加を検討する候補。
3. **initial-access→execution の大乖離（観測0.20 vs 種0.80）は較正対象にしてはならない**。脆弱性インテリは execution 中間段階を報告しない偏りがあり、実カウントでの上書きは予報を歪める。フルキルチェーン追跡データ（EDRテレメトリ等）が必要で、現観測の射程外。

## M7 本運用（第2段階・90日後）への申し送り

- 90日蓄積後、**from別 n≥10** に達した遷移のみ較正対象とする（現状 initial-access のみ該当に近い）。
- 較正は `technique-chains.json` への直接上書きではなく **Issue/PR で差分提案 → 人間レビュー**（行動原則5）。
- **時系列固定**: 予報生成時刻より後に確定した観測のみを的中母数にする（閉ループバイアス対策）。
- **median_days_to_next**: 本プレビューでは未算出（タイムスタンプ非保持のため）。本運用時は observed_date 差分から算出し、≤2日の遷移のみ48-72h予報の根拠に使う。
- **インテリ偏りの補正**: execution/discovery 等の過小報告を踏まえ、観測カウントをそのまま確率にせず、種prior とのベイズ更新（事前=種・観測で更新）を検討する。
