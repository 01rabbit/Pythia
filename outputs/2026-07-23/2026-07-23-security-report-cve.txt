1. CVE-2026-0770 / Langflow
対象: v1.9.0未満
------------------------------------------------------------

優先度: 必須
CVSS: 9.8 (Critical)
状態: KEV登録済み / 実悪用確認 / PoC公開

【24時間以内の変化】
[CISA 2026-07-21] CVE-2026-0770をKEVカタログへ初回登録（BOD 26-04対応期限2026-07-24）
[BleepingComputer 2026-07-22] KEVIntelが2026-06-27以降64ユニークIPから220件超の悪用試行を観測したと報道
[Security NEXT 2026-07-22] 米当局（CISA）によるWordPress・Langflow脆弱性悪用への警戒喚起を国内向けに報道

【概要】
Langflow（AIエージェント構築フレームワーク）のvalidateエンドポイントに渡されるexec_globalsパラメータの検証不備により、未認証の攻撃者がリモートでroot権限のコード実行に至る脆弱性。Trend Microの分析によれば攻撃者はマルウェア配備・AWS認証情報の窃取・環境変数やコンテナメタデータへのアクセス・偵察コマンド実行を試みており、KEVIntelは2026-06-27以降64のユニークIPから220件超の悪用試行を観測した。

攻撃の流れ:
1. 未認証で/api/v1/validate/codeエンドポイントへexec_globalsパラメータを細工したリクエストを送信
2. サーバ側でexec_globalsが検証なく実行され、root権限でコマンド実行
3. AWS認証情報・環境変数・コンテナメタデータを窃取し追加マルウェアを配備

【IoC】
IoC: 確認されず

【監視ポイント】
・[Langflowサーバのアクセスログ・APIリクエストログを監視し、/api/v1/validate/codeへの異常なexec_globalsパラメータを含むリクエストを検知する]
Splunk SPL: index=web sourcetype=langflow* uri_path="*/api/v1/validate/code*" | stats count by src_ip, http_method | where count > 5
Splunk SPL: index=aws sourcetype=aws:cloudtrail eventName=GetCallerIdentity OR eventName=AssumeRole | search src_ip=<Langflowホスト> | table _time, eventName, src_ip
→ 正規のフロー検証呼び出しと悪用リクエストの区別にはexec_globals内のPythonコード片の有無を確認する。社内開発チームのCI/CD経由アクセスは除外する

【参照】
https://www.bleepingcomputer.com/news/security/cisa-orders-feds-to-patch-actively-exploited-langflow-rce-flaw/
https://www.security-next.com/187654
https://www.cisa.gov/known-exploited-vulnerabilities-catalog

2. CVE-2026-63030 / WordPress Core
対象: 6.9.0〜7.0.1（wp2shell RCEチェーン完全版）
------------------------------------------------------------

優先度: 必須
CVSS: 9.8 (Critical)
状態: KEV登録済み / 実悪用確認 / PoC公開

【24時間以内の変化】
[CISA 2026-07-21] CVE-2026-63030をKEVカタログへ初回登録（BOD 26-04対応期限2026-07-24）
[Security NEXT 2026-07-22] 米当局によるWordPress脆弱性悪用への警戒喚起を国内向けに報道

【概要】
WordPress CoreのREST APIバッチルート混同（interpretation conflict）脆弱性。CVE-2026-60137（SQLインジェクション）と連鎖させることで、6.9.0〜7.0.1のデフォルトインストールに対し未認証のリモートコード実行「wp2shell」チェーンが成立する。開示から数時間以内に複数の公開PoCがGitHubへ登場し、Hexastrike・Patchstack等が開示直後からの実環境悪用を確認した。

攻撃の流れ:
1. REST APIバッチエンドポイントへ細工したサブリクエストを送信しルート解釈の混同を誘発
2. CVE-2026-60137（WP_Query author__not_in SQLi）と連鎖しデータベースへ不正アクセス
3. 未認証のままリモートコード実行に至りWebシェルを設置

【IoC】
IoC: 確認されず

【監視ポイント】
・[WebサーバアクセスログでREST APIバッチエンドポイントへの異常リクエストを監視する]
Splunk SPL: index=web sourcetype=access_combined uri_path="*/wp-json/*batch*" | stats count by clientip, uri_query | where count > 3
Splunk SPL: index=web sourcetype=access_combined uri_path="*/wp-json/wp/v2/*" cs_method=POST | search uri_query="*author__not_in*"
→ 正規プラグインのバッチAPI利用と区別するため、未認証（Cookie/Authorizationヘッダなし）でのバッチリクエストを優先的に確認する

【参照】
https://www.tenable.com/blog/wp2shell-cve-2026-63030-cve-2026-60137-frequently-asked-questions-about-remote-code-execution
https://www.security-next.com/187654

3. CVE-2026-60137 / WordPress Core
対象: 6.8.0〜6.8.5（単独）／6.9.0〜7.0.1（RCEチェーン構成要素）
------------------------------------------------------------

優先度: 必須
CVSS: 9.1 (Critical)
状態: KEV登録済み / 実悪用確認 / PoC公開

【24時間以内の変化】
[CISA 2026-07-21] CVE-2026-60137をKEVカタログへ初回登録（BOD 26-04対応期限2026-08-04）
[Security NEXT 2026-07-22] 米当局によるWordPress脆弱性悪用への警戒喚起を国内向けに報道

【概要】
WordPress CoreのWP_Query author__not_inパラメータが未サニタイズでSQLクエリへ組み込まれるSQLインジェクション脆弱性。CVSSはCNA評価では5.9だがCISA-ADPはCVE-2026-63030との連鎖によるRCE成立可能性を踏まえ9.1（Critical）と再評価した。単独でも6.8系に影響するが、6.9系以降ではCVE-2026-63030と連鎖しwp2shell RCEチェーンを構成する。

攻撃の流れ:
1. author__not_inパラメータへ未サニタイズのSQL構文を注入
2. CVE-2026-63030のバッチルート混同と連鎖しデータベース内容を不正操作
3. 6.9系以降ではRCEチェーンが完成し未認証コード実行に至る

【IoC】
IoC: 確認されず

【監視ポイント】
・[WordPress管理画面・REST APIログでauthor__not_inパラメータを含む異常クエリを監視する]
Splunk SPL: index=web sourcetype=access_combined uri_query="*author__not_in*" | stats count by clientip | where count > 3
→ 正規のWP_Query利用（管理画面プラグイン等）との切り分けにはUser-Agent・認証状態を併用する

【参照】
https://www.tenable.com/blog/wp2shell-cve-2026-63030-cve-2026-60137-frequently-asked-questions-about-remote-code-execution
