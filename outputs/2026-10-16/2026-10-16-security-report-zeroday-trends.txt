1. CVE-2026-102764 BeyondTrust Remote Support（旧 Bomgar・アプライアンス内部コンポーネントのメッセージ発信元検証不備→任意ファイル操作／任意ファイルアップロード）（CVSS 9.3）
------------------------------------------------------------
優先度: critical  軸1=15 軸2=4  KEV登録: なし  悪用: 確認  パッチ: あり
影響バージョン: Remote Support（自己ホスト型）。GTIG は『サポート対象の全バージョンで 26.2.3 まで』と記述。SaaS は 2026-10-09 に修正済み。

【24時間以内の変化】
[Google Threat Intelligence Group 2026-10-15] GTIG が CVE-2026-102764 を 2026 年 8 月下旬からゼロデイとして悪用していた活動を公表し、SAWFLY（Web シェル）と BARECLAW（SOCKS5 トンネラー）の配備を ARMORY CASTLE（旧 UNC5221）に帰属。
[BeyondTrust 2026-10-09] SaaS テナントへ修正を適用済み。アドバイザリ BT26-05 は 10-15 に公開。

【概要】
GTIG によれば、BeyondTrust Remote Support のアプライアンスで内部コンポーネントがメッセージの発信元を十分に検証せず、攻撃者が任意ファイル操作（アップロード）を行える。CVE-2026-102764（NVD 記載は CVSS v4.0 9.3）。GTIG は 2026 年 8 月下旬にゼロデイとして悪用された侵入を観測し、追跡中の疑い PRC 関連の諜報アクター ARMORY CASTLE の活動と帰属した（GTIG の記述）。侵入では /app_84304470.php への POST で SAWFLY Web シェルを設置し、/bin/sh を SUID root でコピーして権限昇格、独自 CLI bt-secrets で資格情報金庫をダンプし、ログを削除、管理者ポータルで Jump Item/Team ロールを Administrator に引き上げ、ファイル転送サービスで文書を持ち出した。C2 は WebSocket 上の SOCKS5 トンネラー BARECLAW（TCP 19800）。KEV 未収載（本窓時点）。被害組織名・件数は GTIG が公表していない。

【攻撃フロー】
1. /app_84304470.php への POST でアップロード（ステージング）し、Web ルートへ SAWFLY Web シェル（mangoapi.php）を設置
2. /bin/sh を /usr/bin/dbus-authd にコピーし SUID root を付与して権限昇格、bt-secrets で資格情報金庫をダンプ
3. zz-root-persist スクリプトで NOPASSWD sudoers を追加して永続化、ログを削除
4. 管理者資格情報で管理ポータルへログインし Jump Item/Team ロールを引き上げ、リモートサポートセッション開始とファイル転送で文書を持ち出し（C2 は BARECLAW SOCKS5-over-WebSocket）

【ATT&CK】
T1190 Exploit Public-Facing Application: インターネット側のアプライアンスに対しゼロデイの任意ファイルアップロードを悪用（GTIG）
T1505.003 Web Shell: SAWFLY（PHP Web シェル）を Web ルートへ設置（GTIG）
T1090 Proxy: BARECLAW（SOCKS5-over-WebSocket トンネラー）による通信中継（GTIG）

【暫定緩和策】
- BT26-05 を適用（自己ホスト型 24.3.1 以降は BT26-05-RS）。SaaS は対応不要
- インターネットに公開された脆弱な自己ホスト型アプライアンスは侵害されている可能性があるとみなし、変更前に証拠を保全して外部ログを収集する（攻撃者がオンボックスのログを削除している）
- 侵害確認時・不明時は clean な修正版イメージから再構築し、修正または再構築の後に依存順序で資格情報をローテーションする
- 管理画面を IP 制限、SSO＋フィッシング耐性 MFA、既定 Jump Item ロールを No Access にし、ログは TLS で SIEM へ転送する

【IOC】

Next.js が 10-14 に帯域外の更新を出し、use cache（Cache Components）の RCE（16.0.0〜16.4.0・CVE なし）と SVG 処理（librsvg）の RCE CVE-2026-96889 を修正した。Vercel の評価は 9.5、Red Hat は 7.8 と評価が割れる。Server Actions の DoS も同時修正。悪用報告はない。CVE の付かない 2 件があり npm audit が検出しない可能性がある。

【攻撃フロー】
1. use cache 関数が複数の型付き配列を返す構成、または SVG 最適化を許可した構成で外部入力が処理される
2. サーバー上でコードを実行（Vercel の記述）

【暫定緩和策】
- 16.4.1（v16）または 15.5.28（v15）へ更新し再ビルド・再デプロイする
- v15 では npm ls sharp で 0.35.5 以降を確認する
- SVG のみ未更新の場合は sharp.block で VipsForeignLoadSvg を遮断する

【監視】
SVG 最適化の有効設定（dangerouslyAllowSVG）と next/og の利用箇所を棚卸しする。
