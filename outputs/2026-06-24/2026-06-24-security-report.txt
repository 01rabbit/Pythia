1. CVE-2026-45585 / Microsoft Windows BitLocker（YellowKey — WinRE経由BitLockerバイパス）
対象: Windows 11 24H2 / 25H2 / 26H1（x64）、Windows Server 2022 / 2025（Server Core含む）
------------------------------------------------------------

優先度: 緊急（物理アクセス要・TPM+PIN未設定環境は即時対応必要）
CVSS: 6.8 (Medium) ※物理アクセス必須だがbitlockerを無力化するため実環境影響は重大
状態: ゼロデイ（パッチ提供済み 2026-06-10）/ PoC公開済み / 実悪用未確認
パッチ提供: 2026-06-10 Microsoftがパッチを正式リリース（それ以前はゼロデイ状態）

【24時間以内の変化】
[BleepingComputer 2026-06-24] Nightmare Eclipseが新たに公開した複数のWindowsゼロデイ群（YellowKey / BlueHammer/GreenPlasma等）の続報として、BleepingComputerがYellowKey（CVE-2026-45585）のPoC詳細・攻撃手順・ビデオを報道。TPM-onlyのBitLocker設定を持つデバイスが今も無防備な状態であることが改めて注目された。
[Nightmare-Eclipse GitHub 2026-05-22公開] PoC（YellowKey）がGitHubで公開済み。BleepingComputerでのPoC解説記事が本調査期間内に掲載。

【概要】
Windows回復環境（WinRE）のNTFSトランザクション処理に脆弱性が存在し、攻撃者が細工したFsTxファイルを含むUSBドライブまたはEFIパーティションを対象デバイスに接続してWinREに再起動させ、CTRL長押しで無制限シェルをスポーンできる。スポーンされたシェルはBitLockerで保護されたストレージボリュームに無制限アクセスが可能。TPM-onlyのBitLocker構成が対象であり、TPM+PIN構成は本攻撃に対して耐性を持つ。物理アクセスが必要であるため法人のノートPC・リモートオフィス・出張機材が主な標的となる。Nightmare Eclipseによる一連のWindows脆弱性公開キャンペーンの一環。

攻撃の流れ:
1. 攻撃者が標的デバイスに物理アクセスし、細工したFsTxファイルを含むUSBまたはEFIパーティションを接続する
2. デバイスをWinREに再起動させ、autofstx.exeによるトランザクション処理中にCTRL長押しでシェルをスポーンする
3. BitLockerで暗号化されたボリュームに無制限アクセスし、機密データを抽出・改ざんする

【暫定緩和策】
・BitLocker設定をTPM-onlyからTPM+PIN（またはTPM+StartupKey）へ変更する（PowerShell: manage-bde -protectors -add C: -TPMAndPIN / manage-bde -protectors -enable C:）
・Microsoftが提供した緩和策: autofstx.exeのWinRE自動起動を防ぐ設定を適用（KB5058411 / KB5058413）
・2026-06-10リリースのパッチを適用済みであっても、TPM-only構成のデバイスはTPM+PIN設定への変更を強く推奨

【IoC】
IoC: 確認されず（実悪用未確認・物理アクセス要のため広域IoC収集困難）

【監視ポイント】
・[Windows Event Log / Endpoint Detection] WinRE起動イベント・USBストレージの突然接続・BitLockerキーアクセスログを監視する
Splunk SPL: index=wineventlog (EventCode=1100 OR EventCode=7045 OR EventCode=24577) | eval suspicious=if(EventCode=24577 AND NOT isnotnull(match(Message,"TPM+PIN")),"POTENTIAL_YELLOWKEY","OK") | where suspicious="POTENTIAL_YELLOWKEY" | table _time, host, Message
→ BitLockerステータス監視はGet-BitLockerVolumeのProtectorTypeをSplunkに定期収集し、TPM-onlyホストを特定する優先度が高い

状態: 実悪用確認（2026-06-22〜23 PoC公開後即日攻撃観測）/ PoC公開済み（SSD Secure Disclosure 2026-06-24）/ KEV未登録（近日追加見込み）

4. CVE-2026-8732 / WP Maps Pro WordPress プラグイン（未認証管理者アカウント作成 → サイト完全掌握）
対象: WP Maps Pro 6.1.0以前（インストール数15,000+サイト）
------------------------------------------------------------

優先度: 必須
CVSS: 9.8 (Critical)
状態: 実悪用確認（Wordfence 24h内2,858件ブロック）/ パッチ提供済み（6.1.1）/ KEV未登録

【24時間以内の変化】
[The Hacker News / SecurityWeek 2026-06-24] 「Critical WP Maps Pro Flaw Actively Exploited to Create Admin Accounts」として大規模報道。Wordfenceが過去24時間で2,858件の攻撃ブロックを確認。
[WordPress.org 2026-06-24] 修正版6.1.1がリリース済み。

【概要】
WP Maps Proのサポート一時アクセス機能のAJAXアクション（wpgmp_temp_access_ajax）がwp_ajax_nopriv_フックに登録されており未認証で呼び出し可能。nonceチェックがあるが、nonceはwp_localize_scriptでフロントエンドページに公開されているため誰でも取得可能。check_temp=falseパラメータでwp_insert_user()によるadministratorロールの新規アカウントが作成され、マジックログインURLが返される。攻撃者はこのURLでログインし完全なWordPress管理者権限を得る。対処: 6.1.1への即時更新。更新困難な場合はプラグインを一時無効化する。

攻撃の流れ:
1. 攻撃者がWP Maps Proが有効なサイトのフロントエンドからnonceを取得する
2. wp-admin/admin-ajax.php?action=wpgmp_temp_access_ajaxにcheck_temp=falseでPOSTリクエストを送信し管理者アカウントを作成する
3. 返されたマジックURLでログインし、WordPress管理者としてバックドアプラグイン・ウェブシェルを設置する

【IoC】
IoC: 確認されず（汎用的なWordPress exploit routineによる攻撃のため固有IOCは少ない）
URI: /wp-admin/admin-ajax.php（action=wpgmp_temp_access_ajax かつ check_temp=false）

【監視ポイント】
・[WordPress / Web Access Log] admin-ajax.phpへのwpgmp_temp_access_ajax呼び出しを検知する
Splunk SPL: index=webserver sourcetype=access_combined uri_path="/wp-admin/admin-ajax.php" cs_uri_query="*wpgmp_temp_access*" | stats count by src_ip, _time | where count > 1 | sort -count
→ このAJAXアクションへのアクセスは正常な管理者操作にはほぼ現れない。1件でも検出時はWordPressユーザー一覧を即時確認する
