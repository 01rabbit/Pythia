1. CVE-2026-94127 / F5 BIG-IP Access Policy Manager (APM)
対象: BIG-IPアクセスポリシー+OAuthプロファイルを同一仮想サーバに構成した環境（詳細はF5アドバイザリK000162605参照）
------------------------------------------------------------

優先度: 必須
CVSS: 9.8 (Critical)
状態: KEV登録済み / 実悪用確認 / ゼロデイ

【24時間以内の変化】
[JPCERT/CC 2026-09-24] 既報CVE（2026-09-23付ゼロデイ特報・KEV登録済み）について本日正式に注意喚起を発行（at260028）
[watchTowr Labs 2026-09-24] OAuth UserInfoハンドラのヒープ境界外書き込みの技術解析を公開（0x4100バイト固定バッファへAuthorizationヘッダを未検証コピー）
[CISA KEV 2026-09-25] FCEB期限（dateAdded+3日=2026-09-25）が本日到来。Rapid7が実悪用確認とあわせて改めて周知

【概要】
F5 BIG-IP Access Policy Manager（APM）にヒープベースのバッファオーバーフロー脆弱性CVE-2026-94127が存在し、APMアクセスポリシーとOAuthプロファイルを同一仮想サーバに構成した環境で、未認証の攻撃者がリモートコード実行を達成できる。F5は2026-09-22に修正版を公開すると同時に実悪用を確認しており、CISAは同日KEVカタログへ追加（FCEB期限2026-09-25）した。本日JPCERT/CCが国内向けに正式な注意喚起を発行し、watchTowr LabsとRapid7が技術詳細・脅威動向の分析を追加公開した。データプレーンの問題でありコントロールプレーンは直接影響を受けない。

攻撃の流れ:
1. 攻撃者がAPMアクセスポリシー+OAuthプロファイル構成済みの仮想サーバへ細工したAuthorizationヘッダを送信
2. OAuth UserInfoハンドラのヒープバッファオーバーフローにより制御構造が破壊される
3. リモートコード実行（詳細な悪用後の挙動は非公開）

・APM+OAuthプロファイル構成の有無を全仮想サーバで棚卸しし、該当構成のみ優先対応

2. CVE-2026-87902 / WordPress Core
対象: 4.7.0〜7.1.1（7.1.2で修正・4.7系列までバックポート）
------------------------------------------------------------

優先度: 必須
CVSS: 9.2 (Critical)
状態: 実悪用確認 / PoC公開

【24時間以内の変化】
[Help Net Security 2026-09-23] WordPress 7.1.2でページテンプレート解決処理の未認証ローカルファイルインクルード脆弱性CVE-2026-87902を修正したと報道（窓外だが背景情報として記録）
[The Hacker News 2026-09-24] パッチ公開から数時間後の2026-09-22 11:49 UTCにPatchstackが初回悪用試行を観測したと報道。Previdianの遠隔測定で少なくとも68件の悪用試行を確認

【概要】
WordPress Coreのページテンプレート解決処理（get_page_template()）に未認証のローカルファイルインクルード脆弱性CVE-2026-87902が存在し、特定のテーマ構成（page-で始まる最上位ディレクトリを持つ子/親テーマ）とサーバ環境の条件が揃った場合はリモートコード実行に至る。WordPress.orgは2026-09-22に7.1.2（4.7系列までバックポート）で修正し、その数時間後にはPatchstackが最初の悪用試行を観測した。The Hacker Newsの報道によれば、Previdianの遠隔測定で少なくとも68件の悪用試行が確認されており、攻撃はpearcmd.php等のローカルPHPファイルを読み込ませGitHubホストの外部スクリプトを取得させる手口が中心となっている。WordPressは既定で自動更新が有効なため大量侵害には至っていないとみられるが、自動更新を無効化した環境や旧バージョンを塩漬けにした環境はリスクが高い。

攻撃の流れ:
1. 未認証の攻撃者がページテンプレート解決パラメータを細工しサーバ上の読み取り可能なローカルPHPファイルを指定
2. テーマディレクトリ構成等の条件が揃った環境で当該ファイルがテンプレートとしてインクルードされる
3. 外部ホストのペイロード取得・実行によるリモートコード実行（条件付き）

【IoC】
IoC: 確認されず

【監視ポイント】
・[WordPressのページテンプレートパラメータ経由の異常なファイルパス指定・/tmp配下への書き込みを監視]
Splunk SPL: index=web_access sourcetype=access_combined uri_query="*page_template*" (uri_query="*pearcmd*" OR uri_query="*..*") | table _time clientip uri_query status
→ WordPress自動更新の有効化状況とバージョン7.1.2以降への更新有無を資産棚卸しで確認する。page-始まりディレクトリを持つテーマの利用有無を優先確認

対象: 1.6.x（1.6.16未満）/ 1.7.x（1.7.1未満）

【概要】
Roundcube Webmailのvirtuser_queryプラグインに未認証のSQLインジェクション脆弱性CVE-2026-48842が存在し、preg_replace()によるバックスラッシュエスケープ処理の不備を突いて認証前にデータベースクエリを改ざんできる。カナダサイバーセキュリティセンター（CCCS）がOSSコミュニティ報告に基づき実悪用進行中と警告し、BleepingComputer等複数の海外メディアが後追い報道した。Roundcubeは1.6.16 / 1.7.1で修正済みだが、Roundcubeは国内含む多くのホスティング事業者で採用されているWebメールであるため波及が懸念される。即時更新が困難な場合はvirtuser_queryプラグインの無効化が推奨される。

攻撃の流れ:
1. 未認証の攻撃者がログイン画面等からvirtuser_query処理へ細工した入力を送信
2. バックスラッシュエスケープのバイパスによりSQL文が意図しない形で改ざんされる
3. データベース内容の窃取・改ざん（認証バイパスを含む高難度攻撃と評価）
