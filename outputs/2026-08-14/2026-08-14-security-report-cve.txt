1. CVE-2026-59310 / VMware vCenter Server
対象: vCenter Server 未パッチ版（VMSA-2026-0006、2026-07-29公開の修正を未適用の環境）
------------------------------------------------------------

優先度: 高
CVSS: 9.8 (Critical)
状態: 実悪用確認

【24時間以内の変化】
[BleepingComputer 2026-08-14] vCenter Syslogサーバのディレクトリトラバーサル脆弱性が悪用されreverse_sshによる永続的リモートアクセスが確立されていることが判明
[Rapid7 2026-08-13] CVE-2026-59309（認証バイパス）とCVE-2026-59310（RCE）の技術解析ブログを公開
[Dark Reading 2026-08-14] グローバルな攻撃キャンペーンとして報道、361件のユニークな被害IPアドレスが47カ国で確認されたと報告

【概要】
Broadcomが2026-07-29に公開したvCenter Server Syslogサーバの未認証ディレクトリトラバーサル脆弱性（CWE-22、CVSS9.8）が、開示から5日後の2026-08-03からAPT水準の攻撃者により実悪用されていることが判明した。パストラバーサルによるファイル書き込みから任意コード実行に至り、攻撃者はcronジョブを設置してreverse_sshによる永続的リモートアクセスを確立している。QUIRSOの観測では47カ国361件のユニークな被害IPアドレス（ドイツ・米国・トルコ・イラン・フランスに集中）が確認されており、CISA KEVへの登録は本日時点で未確認。

攻撃の流れ:
1. 未認証でvCenter Syslogサーバへディレクトリトラバーサルリクエストを送信
2. 任意ファイル書き込みからコード実行に至り、悪意あるcronジョブを設置
3. reverse_sshで永続的なリモートアクセスを確立し被害環境内で活動を継続

【IoC】
IoC: 確認されず

【監視ポイント】
・[vCenter Server の Syslog / Web アクセスログおよびcronジョブ変更を監視する]
Splunk SPL: index=vmware sourcetype=vcenter_syslog uri_path="*..%2f*" OR uri_path="*..\\/*" | stats count by src_ip
Splunk SPL: index=linux sourcetype=cron (action=create OR action=modify) NOT user=root | table _time host cron_entry user
→ vCenter管理インターフェースの直接インターネット露出有無を確認し、cronエントリの新規追加・reverse_ssh関連プロセス（ssh -R 等）の起動有無を優先確認する

2. CVE-2026-71362 / Adobe Commerce / Magento Open Source
対象: Commerce, Commerce B2B, Magento Open Source（2026年7月パッチまでの各バージョン）
------------------------------------------------------------

優先度: 高
CVSS: 9.1 (Critical)
状態: 実悪用確認

【24時間以内の変化】
[BleepingComputer 2026-08-13] Adobeが認可不備の脆弱性を修正するアドバイザリを公開した直後からSansecが実悪用の試行をブロックしたと報告
[SecurityWeek 2026-08-13] 開示からわずかな時間で攻撃が開始されたと報道

【概要】
Adobe Commerce / Magento Open Sourceのセッション処理においてカスタマーIDとセッションの紐付けが不適切な脆弱性（CWE-863、CVSS9.1）が発見され、Adobeが2026年8月パッチで修正した。既存アカウント・管理者権限・ユーザー操作を必要とせずセッションを別顧客のアカウントへ切り替えられるため、未認証の攻撃者が顧客アカウントを乗っ取れる。Adobeのアドバイザリ公開直後からSansecが実悪用の試行を検知・ブロックしたと報告しており、開示から短時間で武器化された。

攻撃の流れ:
1. 未認証で対象ECサイトのセッション識別処理に対しリクエストを送信
2. セッションが別の既存顧客アカウントへ切り替わる
3. 乗っ取った顧客アカウントの決済情報・個人情報へアクセス

【IoC】
IoC: 確認されず

【監視ポイント】
・[Adobe Commerce / Magentoのセッションログ・アカウント切り替え挙動を監視する]
Splunk SPL: index=web sourcetype=magento_access uri_path="*/customer/account*" | stats dc(session_id) by src_ip | where dc(session_id) > 5
→ 同一IPから短時間に複数の顧客セッションが生成・切り替わっていないかを確認する。パッチ未適用環境は最優先で適用する
