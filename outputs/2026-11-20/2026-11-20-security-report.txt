AI-2026-11-20-001 [カテゴリA] 欧州委員会がサイバー攻撃を公表、CERT-EU は AI 攻撃ツール『ARTEX』の使用を特定：10-22 に初兆候を検知、人事系システム（給与・休暇・医療償還・翻訳）が 10 日以上停止、データ侵害の証拠・身代金要求はなし、帰属なし
------------------------------------------------------------
The Record によれば、欧州委員会は 2026-11-19、先月（2026-10）サイバー攻撃を受けたことを確認した。報道官 Thomas Regnier は初兆候を 10-22 に検知したとし、これを『AI 生成のサイバーキャンペーン』と表現したが、使用ツールや攻撃者の動機は特定しなかった。The Record は、POLITICO が本件を初報し、CERT-EU が攻撃者による『ARTEX』（商用 AI モデルで脆弱性発見と悪用を自動化するオープンソースの AI ハッキング基盤・7 月公開）の使用を特定したと報じた。FBI は先週、ARTEX が犯罪者と国家支援グループに使われていると警告していた。影響で人事系システム（給与・休暇申請・医療償還・翻訳サービス）が 10 日以上停止し、委員会は防御措置として複数サービスを一時停止、CERT-EU と欧州データ保護監察機関（EDPS）と連携して他システムを点検している。Regnier は職員データの広範な侵害の証拠は無く、身代金要求も認識していないと述べた。本件は 2026 年に公表された委員会の 3 件目のインシデント（1 月 Ivanti・3 月クラウド基盤）だが関連は示されていない。攻撃者・グループの名指しは無く、唯一名指しされたのは CERT-EU 経由の ARTEX である。『AI による脆弱性発見・悪用の自動化が国家機関の実被害に至った』事例として、AI エージェント悪用（A4）の観測対象とする。
  被害規模: 人事系システムが 10 日以上停止（給与・休暇申請・医療償還・翻訳）。複数サービスを防御措置として一時停止。広範な職員データ侵害の証拠は無く、身代金要求も認識していないと欧州委員会は説明。
  監視: ARTEX 等の AI 攻撃基盤に特徴的な自動化スキャン・悪用試行を監視する。公開系サービスの脆弱性を優先的に塞ぐ。

CVE-2026-123890 [high] VMware vCenter Server（VMware Directory Service の SRP-6a セッション鍵漏えいによる認証バイパス・administrator@vsphere.local としてのセッション確立・ゼロデイ悪用）
------------------------------------------------------------
対象: Broadcom（VMware） / vCenter 8.0・9.0・9.1、および VMware Cloud Foundation／vSphere Foundation／Telco Cloud Platform／Telco Cloud Infrastructure 同梱の vCenter（Cloud Foundation 5.x を含む）。vSphere 6.5／6.7／7.0 は評価対象外だが影響ありと推定（The Hacker News）。GTIG は VCSA 7.x・8.x での悪用を記述
評点: CVSS v3 9.8
【概要】
Broadcom は 2026-11-19、VMware vCenter の VMware Directory Service（vmdir）における認証バイパス CVE-2026-123890（CVSS 9.8・Mandiant 発見）を公開した。The Hacker News によれば vCenter 8.0／9.0／9.1 と VCF・VVF・Telco Cloud 同梱版が対象で、Enhanced Linked Mode の有無に関係なく影響し、回避策は無く、修正版は全サポート系列に提供された。同日 Google Threat Intelligence Group（GTIG）は、『疑われる PRC 系の諜報アクター ARMORY CASTLE（旧 UNC5221）』が 2026 年 9 月上旬、BeyondTrust Remote Support のゼロデイ（CVE-2026-102764・既報 10-16）で得た足場から、未認証の SRP-6a セッション鍵漏えい（vmdird の DCE/RPC・TCP 2012・UUIDv1 時刻の予測可能性）を Go 製ツール BONESAW で悪用し、administrator@vsphere.local のセッションを確立、data.mdb から STS SAML 署名鍵を抽出して SAWSNAKE で Golden SAML を実施、SSO 管理者とマシンアカウントを作成、VAMI API で SSH を有効化し、ESXi では vmfs_browser.py でゲスト VM ディスクから NTDS・SYSTEM・SECURITY・DNS を抜き出したと公表した。GTIG は『疑われる』の表現を保ち、標的の業種・国は記述していない。Broadcom 側は THN に対し悪用の報告は無いと述べており、ベンダー見解と GTIG の報告が同日に食い違う。CISA KEV はカタログ 2026.11.18 で未収載。vCenter の認証バイパスは 2026-07 の CVE-2026-59309（既報・QUIRSO が中国系と疑われるアクターの悪用を報告）に続くもので、仮想化基盤の管理面がゼロデイ悪用の対象となる状況が続いている。
【一時緩和】

  - vCenter の TCP 2012（vmdird RPC）・443・22・5480 を許可リスト IP 以外から遮断する（Mandiant の vcsa-hardening-tool は iptables の既定拒否と SIEM 転送を設定）
  - VAMI API（5480）への PUT /rest/appliance/access/ssh、vsphere.local の新規管理者アカウント、ESXi の root authorized_keys 追加、VMFS 上の隠しディレクトリ『.a』を点検する

  - T1606 (credential-access): GTIG が、BONESAW が data.mdb から STS SAML 署名鍵を抽出し、SAWSNAKE で SAML アサーションを偽造（Golden SAML）したと記述

CVE-2026-76466 [high] Cisco Expressway Core／Expressway Edge（クラスタ構成時のデータベースサービスの永続 Cookie による未認証 root コマンド実行）
------------------------------------------------------------
対象: Cisco / クラスタ構成の Expressway Core／Edge（仮想・アプライアンス）。X15.5.20 で修正。X14 以前は修正済み系列への移行が必要（SecurityWeek の記述）
評点: CVSS v3 9.8 / EPSS 0.00417
【概要】
SecurityWeek によれば、ロシアのセキュリティ企業 F6 は、Cisco Expressway Core／Edge の重大な脆弱性 CVE-2026-76466（CVSS 9.8）が、GitHub（dinosn/cve-2026-76466）での PoC 公開の直後に実際の攻撃で悪用され、ロシアの 1 組織（名称非公表）が侵害されたと報告した。脆弱性は Expressway のデータベースサービス機能の永続 Cookie に起因し、Cookie を持つ攻撃者が未認証でデータベースサービスへ到達して RPC コマンドを発行し root でコマンドを実行できる。クラスタ構成の機器のみが対象で、Cisco は 2026-10-21 に勧告（cisco-sa-vcs-static-cred-hr7EWZ8t）を公開し X15.5.20 で修正、回避策は無い。F6 の調査では攻撃者がインターネットに露出した Expressway X15.5.3 2 台を侵害し、内部のクラスタノード 2 台へ展開、root 取得後に SMB・SQL Server・WinRM・GitLab のリポジトリから資格情報を探索する独自 Python スクリプトを準備した。スクリプトのコメントには AI アシスタント利用を示す記述があり、その場で改変されていたという。F6 は帰属を行っておらず、Cisco の勧告は改訂されず『公開の悪用の認識なし』のままである。F6 は Erlang システムログでの検知と、TCP 4371〜4372 のクラスタノード以外からの遮断を推奨している。CISA KEV はカタログ 2026.11.18 で未収載。
【一時緩和】
  - Expressway Core／Edge を X15.5.20 以降へ更新する（回避策なし）。X14 以前は修正済み系列へ移行する
  - 即時更新できない機器は TCP 4371〜4372 を信頼済みクラスタノード IP 以外からファイアウォールで遮断する（F6 の推奨）
  - Expressway の Erlang システムログ、想定外の Python 実行・SMB／WinRM／SQL 探索、GitLab リポジトリへの資格情報検索を点検する
【TTP】
  - T1190 (initial-access): F6（SecurityWeek 経由）が、攻撃者がインターネットに露出した Expressway X15.5.3 2 台を CVE-2026-76466 で侵害し、内部のクラスタノード 2 台へ展開したと記述
  - T1046 (discovery): F6 が、root 取得後に SMB 共有・SQL Server・WinRM・GitLab を探索する独自 Python スクリプトを準備したと記述
【IOC】IP: なし / ファイル: なし
【監視】Expressway のデータベースサービス（TCP 4371〜4372）への外部からの RPC、Erlang システムログの異常、Expressway から内部ネットワークへの SMB／WinRM／SQL 接続を監視する。
