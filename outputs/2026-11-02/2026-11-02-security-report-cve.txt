CVE-2026-97229 GitLab CE/EE（Onigmo 整数オーバーフロー・CI/CD 設定経由の未認証 RCE）
------------------------------------------------------------
優先度: high  軸1=9 軸2=7  KEV登録: あり  悪用: 確認  PoC: 公開  パッチ: あり  CVSS v3: 10.0
影響バージョン: GitLab CE/EE 19.2.8／19.3.5／19.4.2 未満（Onigmo の整数オーバーフロー・Ruby 側の修正も必要）。Alpine は 19.3.4 を導入後、19.3.6 でも Ruby 未修正のため残存
KEV追加日: 2026-10-29

【24時間以内の変化】
[BleepingComputer 2026-11-01] Alpine Linux が 10-20〜21 の悪用試行（ワーカー 8 回クラッシュ・うち 4 回は部分的に成功・完全成功は確認されず）を受け、GitLab を再構築し全パスワードをリセット。攻撃者が GitLab コンテナイメージをダウンロードしており、サプライチェーン攻撃の準備の可能性。[続報]

【概要】
Alpine Linux は、開発基盤の GitLab に対し 10-20〜21 に CVE-2026-97229 を狙った悪用試行があったとして、GitLab を再構築し全パスワードをリセットした（BleepingComputer）。攻撃者は細工した CI 設定を送り、ワーカーを 8 回クラッシュさせ、うち 4 回は部分的に成功したが完全な成功は確認されていない。Alpine は 10-27 までリポジトリのコミット・パッケージ・リリースの改ざんは見つかっていないとする。署名鍵は GitLab サーバー上になく露出していない。一方でログ欠落と外向き通信記録の不在によりコード実行を否定できないため、再構築を選んだ。攻撃者が GitLab のコンテナイメージをダウンロードしていた点を、記事はサプライチェーン攻撃準備の可能性として挙げる（推測）。原因は、Alpine が 19.3.4 を導入し、19.3.6 でも Ruby 側の修正が自社イメージに無かったこと。本 CVE は CISA KEV に 10-29 収載済みで、攻撃者の帰属はない。

【攻撃フロー】
1. 攻撃者が細工した CI/CD 設定（悪意ある正規表現）を Alpine の GitLab へ送信（10-20〜21）
2. Onigmo の整数オーバーフローによりワーカーが 8 回クラッシュ、4 回は部分的に成功（完全成功は確認されず）
3. GitLab のコンテナイメージをダウンロード（目的は不明・サプライチェーン準備の可能性は推測）

【TTP】
- T1190 Exploit Public-Facing Application: 攻撃者が細工した CI 設定（正規表現）を送信して GitLab の脆弱性を突き、ワーカーを 8 回クラッシュさせた（BleepingComputer）

【暫定緩和策】
- GitLab を修正版へ更新し、同梱／ベースの Ruby も修正済みであることを確認する（カスタムコンテナ・自前ビルドは特に注意）
- ログと外向き通信記録を保全し、侵害を否定できない場合は再構築と全パスワード・CI/CD シークレットの交換を検討する

【監視】
CI/CD の設定に含まれる異常な正規表現、GitLab ワーカーの繰り返しクラッシュ、GitLab コンテナイメージの不審なダウンロードを確認する。
IOC は記事に記載なし。Alpine はログ欠落と外向き通信記録の不在のためコード実行を否定できないと説明（侵害の確認ではない）。

【参照】
- Alpine Linux rebuilds GitLab after attempted RCE attack (BleepingComputer) https://www.bleepingcomputer.com/news/security/alpine-linux-rebuilds-gitlab-after-attempted-rce-attack/

CVE-2026-112816 Canonical LXD／MicroCloud（信頼済みクライアントのなりすましによる認証回避）
------------------------------------------------------------
優先度: medium  軸1=8 軸2=3  KEV登録: なし  悪用: 未確認  PoC: 未確認  パッチ: あり  CVSS v3: 10.0
影響バージョン: LXD 4.0.14／5.0.10／5.21.8／6.9 のそれぞれ修正版より前、および MicroCloud（版は記事に記載なし）。Ubuntu アーカイブ版 LXD は対象外と記載

【24時間以内の変化】
[The Hacker News 2026-11-01] CVSS 10.0 の LXD／MicroCloud の認証回避 CVE-2026-112816 を THN が報道。修正版を公開済み。悪用・PoC の報告なし。[新規]

【概要】
Canonical の LXD と MicroCloud に、攻撃者が信頼済みクライアントの秘密鍵を持たずにそのクライアントとして認証される欠陥（CVE-2026-112816・CVSS 10.0）が見つかった（THN）。成立には HTTPS API へのネットワーク到達性と、なりすます対象の公開証明書が必要。成功するとそのクライアントの権限でクラスターと仮想マシンを操作できる。Incus コミュニティ（LXD のフォーク）が報告し Incus 7.6.0 で修正された。CISA の評価（10-30）では悪用は確認されていない。未検証の情報として、修正版が stable チャネルへ展開中であり利用者は自分の版を確認する必要がある。

【攻撃フロー】
1. 攻撃者が LXD／MicroCloud の HTTPS API へ到達し、信頼済みクライアントの公開証明書を入手する（THN の前提条件）
2. 秘密鍵なしにそのクライアントとして認証され、クラスターと VM を操作できる（THN）

【TTP】
- T1190 Exploit Public-Facing Application: HTTPS API へネットワーク到達でき、信頼済みクライアントの公開証明書を知る攻撃者が、秘密鍵なしにそのクライアントとして認証される（THN）

【暫定緩和策】
- LXD／MicroCloud の HTTPS API を信頼できるネットワークに限定する
- 修正版（stable への展開状況を確認）へ更新する

【監視】
LXD の HTTPS API（既定 8443）への未知の送信元からの接続、信頼済みクライアント証明書による想定外の送信元からのアクセスを確認する。
悪用・PoC の報告なし（CISA の評価〈10-30〉は悪用既知ではない・THN）。NVD の収載状況と EPSS は未確認。

【参照】
- CVSS 10.0 LXD, MicroCloud Flaw Lets Attackers Impersonate Trusted Clients Without a Private Key (The Hacker News) https://thehackernews.com/2026/11/critical-lxd-and-microcloud-flaw-cvss.html
