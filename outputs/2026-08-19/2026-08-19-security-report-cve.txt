1. CVE-2026-33824 / Internet Key Exchange (IKE) Service Extensions
対象: Windows 10 (1607/1809/21H2/22H2)、Windows 11 (22H3/23H2/24H2/25H2/26H1)、Windows Server 2016以降のうち2026年4月14日公開の月例セキュリティ更新未適用の全ビルド（例: Windows 10 1607は10.0.14393.9060未満、Windows 11 26H1は10.0.28000.1836未満が該当）
------------------------------------------------------------

優先度: 必須
CVSS: 9.8 (Critical)
状態: KEV登録済み / 実悪用確認 / PoC公開

【24時間以内の変化】

【概要】
Microsoft WindowsのIKE (Internet Key Exchange) Service Extensionsに存在する二重解放（double free、CWE-415）の脆弱性で、CVSSv3.1は9.8（Critical、AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H）である。IKEv2のフラグメント再構成処理においてSecurity Realm Vendor IDペイロードが確保するヒープメモリへの参照がシャローコピーされ、IkeDestroyPacketContextとIkeFreeMMSAの双方から解放されることで二重解放が発生し、認証不要・ユーザー操作不要のネットワーク経由でIKEEXTサービス（SYSTEM権限）上での任意コード実行に至る。Microsoftは2026年4月14日の月例パッチで修正済みだが、CISAは2026年8月18日にKEVカタログへ新規追加した。Zero Day Initiative(ZDI)が悪用メカニズムの技術解説を公開しており、コミュニティのPoCリポジトリにも該当CVEを対象としたコードの存在が確認できるが、本CVE単体を対象とした独立した実悪用観測レポート（ベンダー確認・ハニーポット観測等）は本調査時点で確認できておらず、CISAのKEV登録自体が実悪用の主要な根拠である点は未確認情報として明記する（推測）。

攻撃の流れ:
1. 攻撃者がWindows端末のUDP 500/4500ポート（IKE / NAT-T IKE）へ、Microsoft Security Realm Vendor IDを含むIKE_SA_INITメッセージをネットワーク経由で送信する
2. 続けて複数の暗号化フラグメント（SKF）ペイロードから成る不正なIKE_AUTHメッセージを送信し、フラグメント再構成処理でヒープメモリのシャローコピーを発生させる
3. IkeDestroyPacketContextとIkeFreeMMSAの双方で同一メモリ領域が解放される二重解放（double free）がトリガーされ、IKEEXTサービス（SYSTEM権限）のコンテキストで任意コード実行に至る（推測: ZDI技術解説に基づく再構成であり、実際の攻撃者コードの詳細は未確認）

2. CVE-2026-55040 / SharePoint
対象: Microsoft SharePoint Enterprise Server 2016（16.0.5561.1001未満）、SharePoint Server 2019（16.0.10417.20175未満）、SharePoint Server Subscription Edition（16.0.19725.20434未満）
------------------------------------------------------------

優先度: 必須
CVSS: 9.1 (Critical)
状態: KEV登録済み / 実悪用確認 / PoC公開

【24時間以内の変化】
[CISA KEV Catalog 2026-08-18] CISAがCVE-2026-55040をKEVカタログへ新規追加（dateAdded 2026-08-18・FCEB対応期限2026-08-21）。Rapid7が2026-08-11に公開したPoC後、実悪用が急拡大したことを受けた追加

【概要】
Microsoft SharePoint（Enterprise Server 2016 / Server 2019 / Subscription Edition）に存在する弱い認証（weak authentication、CWE-1390）の脆弱性で、CVSSv3.1は9.1（Critical、AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N）である。JWTトークン検証処理の4つの弱点を組み合わせることで、未認証の攻撃者が外側ヘッダに"alg: none"を指定し署名検証を回避したJWTを作成し、SharePoint自身のSTS証明書サムプリントで署名鍵解決処理を悪用したうえで検証されないダミー署名を付与することで、管理者を含む任意のSharePointユーザーになりすますことができる。Microsoftは2026年7月14日のPatch Tuesdayで修正済みだが、Rapid7が2026年8月11日に技術解説とPoCスクリプトを公開した数時間後から実悪用が急拡大し、KEVIntelは2026年7月19日以降計12件の悪用試行（うち8件が8月12〜13日に集中）を記録している。CISAは2026年8月18日にKEVカタログへ新規追加した。インターネットに露出したオンプレミスSharePointサーバは8,500台超が未パッチのまま残っているとの報道がある。

攻撃の流れ:
1. 攻撃者が未認証のままSharePointサーバへHTTPリクエストを送信し、外側ヘッダに"alg: none"を指定したJWTを提示して署名検証を回避する
2. SharePoint自身のSTS証明書サムプリントを利用した署名鍵解決処理の不備を突き、検証されないダミー署名（例: "AAAA"）を付与したトークンを渡す
3. 偽造JWTが正規トークンとして受理され、管理者を含む任意のSharePointユーザーへなりすまし、文書の閲覧・改ざん・データ窃取や広域Microsoft 365環境への横展開の足がかりを得る

対象: macOS Sonoma 14.8.9未満 / macOS Sequoia 15.7.9未満 / macOS Tahoe 26.6.1未満（画面共有 screensharingd を有効化している端末）

【概要】

2. screensharingdの認証状態管理の不備により、有効な認証情報なしで画面共有セッションの確立に成功する
3. root権限でのコマンド実行を確立し、Moneroマイニングソフトウェアを設置して不正マイニングを行う（NCSC-NL確認事例）
