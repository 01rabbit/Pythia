1. CVE-2026-20253 / Splunk Enterprise（PostgreSQLサイドカーサービス 未認証RCE）
対象: Splunk Enterprise 10.2.0〜10.2.3、10.0.0〜10.0.6
------------------------------------------------------------

優先度: 必須
CVSS: 9.8 (Critical)
状態: KEV登録済み / 実悪用確認 / PoC公開

【24時間以内の変化】
[Security NEXT 2026-06-19] 「6月公表のSplunk Enterprise脆弱性、悪用を確認」として国内報道。SplunkおよびCISAが注意を呼びかけ。
[CISA KEV 2026-06-18] CVE-2026-20253をKEVカタログへ追加。FCEB機関への対応期限が本日（2026-06-21）到来。
[Help Net Security / SecurityWeek 2026-06-19] PoC公開から実悪用確認まで6日という異例の短期間での武器化を報告。

【概要】
Splunk Enterprise内のPostgreSQLサイドカーサービスのエンドポイントが認証チェックを一切実施していないため、ネットワーク到達可能な未認証攻撃者が任意のファイル作成・切り詰め操作を行える。攻撃者はPostgreSQLのlo_export関数を悪用してBLOBをファイルとしてサーバのファイルシステムへ書き出し、SplunkのWARファイルディレクトリへWebシェルを配置することでRCEに昇格できる。Splunk PSIRTは2026-06-18付けのアドバイザリ更新で「限定的だが実悪用を確認」と明記。Splunkはセキュリティデータを一元管理するSIEM製品であり、侵害された場合はストアされた全ログ・認証情報・接続先情報へのアクセスならびに監視インフラ全体の無効化につながる高影響インシデントとなる。

攻撃の流れ:
1. 攻撃者がネットワーク経由でSplunk Enterprise上のPostgreSQLサイドカーサービスエンドポイントに認証なしでアクセスする
2. lo_export関数を呼び出し、攻撃者制御のBLOBをSplunkのデプロイ可能ディレクトリ（例: $SPLUNK_HOME/etc/apps/）にWebシェルとして書き出す
3. Webシェル経由で任意コードを実行し、Splunkサービスアカウント権限でホスト全体を掌握・ラテラルムーブメントへ展開する

【IoC】
IoC: 公開された具体的なC2 IP・ドメイン・ハッシュは確認されず（限定的悪用段階）

【監視ポイント】
・[Splunk _internal / SplunkdログSIEM] PostgreSQLサイドカーサービスへの不審なエンドポイントアクセスおよびファイル作成操作を監視する
Splunk SPL: index=_internal source=*splunkd.log (pg_sidecar OR postgresql OR lo_export) (create OR truncate OR write) | table _time, host, component, log_level, message | sort -_time
→ サービスアカウント以外のソースIPや通常とは異なる時間帯のアクセスが検知された場合は即時隔離を検討する

・[Splunk _audit / _introspection] Splunk内部でのアプリ追加・WAR展開イベントを監視する
Splunk SPL: index=_audit action=app_install OR action=app_upload | table _time, host, user, info, _raw | sort -_time
→ 管理者以外のユーザーや自動化パイプライン外のアプリ追加イベントはマルウェア配置の可能性がある

・[ネットワークフローログ] PostgreSQLサービスポート（デフォルト8191）への外部IPからの接続を監視する
Splunk SPL: index=network sourcetype=firewall dest_port=8191 | stats count by src_ip, dest_ip | where count > 5 | sort -count
→ SplunkクラスターピアやIDX以外のIPからポート8191へのアクセスは即時精査対象とする

・CVE-2026-42530 / NGINX Open Source（HTTP/3 Use-After-Free RCE）
CVSSv3.1: 8.1（High）/ CVSSv4.0: 9.2（Critical）
状態: パッチ提供済み（2026-06-17）/ PoC未確認 / 悪用未確認
------------------------------------------------------------

【24時間以内の変化】
[F5 / nginx.org 2026-06-17] 緊急アドバイザリおよびnginx 1.31.2リリース。CVSSSv4スコア9.2として公開。
[Security NEXT 2026-06-18] 「nginxに複数のクリティカル脆弱性 – 修正版が公開」として国内報道。有償・OSSともに影響と明記。
[The Hacker News / BleepingComputer 2026-06-18] 複数英語メディアが即日報道。バースト検出閾値（3件以上）到達確認。

【概要】
NGINX Open SourceのHTTP/3モジュール（ngx_http_v3_module）に Use-After-Free の脆弱性が存在する。攻撃者は細工したHTTP/3 QUICセッションを送信してQPACKエンコーダストリームを強制的に再オープンさせることでメモリ破壊を引き起こし、ASLRが無効またはバイパス可能な環境ではNGINXワーカープロセス権限でのRCEが可能となる。HTTP/3を有効化している環境のみ影響を受ける。現時点で実悪用は確認されていないが、CVSS 9.2の評価と緊急パッチリリースを受けて攻撃者による分析・PoC開発が進行中とみられる。対処: NGINX Open Source 1.31.2以降、NGINX Plus R34 p1以降へアップデート。暫定緩和策としてlistenディレクティブからquicを削除してHTTP/3を無効化する。

【IoC】
IoC: 確認されず（悪用未確認段階）

【監視ポイント】
・[Webサーバアクセスログ / SIEM] HTTP/3(QUIC)セッション確立の異常パターンおよびワーカープロセスクラッシュを監視する
Splunk SPL: index=nginx sourcetype=nginx:access http_version="HTTP/3" status>=500 | stats count by clientip, status | where count > 10 | sort -count
→ 同一IPからHTTP/3経由で大量の5xxエラーが発生している場合は悪用試行の可能性があるため送信元をブロックして調査する

・[システムログ] nginx子プロセスの異常終了イベントを監視する
Splunk SPL: index=syslog sourcetype=syslog message="nginx: *worker process*exited*" | table _time, host, message | sort -_time
→ 短期間に複数のworker crashが発生している場合は脆弱性悪用試行の指標として精査する

採用契機: P（新規キャンペーン全容初報）、R（GentleKillerフレームワーク新規マルウェア発見）、S（BYOVD多バリアント・即時PoC武器化の新規TTP）

地域: 東南アジア・南米・西欧を中心に70カ国以上（US一極集中なし）

【24時間以内の変化】
[ESET WeLiveSecurity 2026-06-18] 「Killing me gently: Inside Gentlemen's EDR killer framework」として詳細技術分析を公開。ESET独自追跡による内部データリーク（2026-05）の分析結果を含む。
[BleepingComputer 2026-06-19] 「Gentlemen ransomware uses multiple EDR killers to disable defenses」として追加報道。バースト閾値（3件以上）到達。
[The Hacker News / SecurityAffairs 2026-06-19] 複数メディアが独立して確認。478被害組織・70カ国以上という規模を各誌が報告。

【概要】
Gentlemenは2025年後半に活動を開始した RaaS（Ransomware-as-a-Service）グループで、元 Qilin アフィリエイトの hastalamuerte が設立したとされる。同グループの最大の特徴は、独自開発した EDR キラーフレームワーク「GentleKiller」にある。GentleKiller は BYOVD（Bring Your Own Vulnerable Driver）技術を使い、Kaspersky アンチウイルス・Valorant（ゲームクライアント）・Javelin・WatchDog 等の正規ソフトウェアに偽装した 8 つの異なるバリアントを持ち、それぞれ異なる脆弱なカーネルドライバを悪用して 48 ベンダーの 400 以上のセキュリティプロセス（CrowdStrike Falcon・SentinelOne・ESET・Microsoft Defender・Kaspersky・Palo Alto Cortex等）を停止させる。新規 BYOVD PoC が公開されると数日以内に武器化するという異常な開発速度を持ち、ESET 内部調査で累計 478 被害組織・70 カ国以上への影響が確認されている。アフィリエイト参加時に GentleKiller 一式＋HexKiller・ThrottleBlood・HavocKiller の外部製 EDR キラー3点セットが標準提供される「EDR キラー込みの RaaS」として台頭している。

攻撃の流れ（判明分）:
1. フィッシングメール・露出したRDP/VPN・初期アクセスブローカー経由で企業ネットワークに侵入し、管理者権限を取得する
2. GentleKillerバリアントを正規ソフトウェアに偽装してデプロイし、脆弱なカーネルドライバをロードしてEDR/AV製品の全プロセスをカーネルレベルで強制終了する（BYOVD）
3. GentleNoteランサムウェアを展開してファイルを暗号化し、二重恐喝（身代金要求＋データリーク脅迫）を実行する

【新規TTP】
・[T1562.001 / Impair Defenses: Disable or Modify Tools] BYOVD による EDR カーネルレベル強制停止 — 8種類の脆弱ドライバを切り替えて特定のドライバをブロックされても別バリアントで継続
・[T1036 / Masquerading] GentleKiller 各バリアントが Kaspersky・Valorant・Javelin・WatchDog等の正規ソフトウェアの証明書・ファイル名を偽装
・[T1543.003 / Create or Modify System Process: Windows Service] 脆弱ドライバをWindowsサービスとして登録して永続的なカーネルアクセスを確立

【IoC】
Hash: ESET malware-ioc リポジトリに GentleKiller バリアントのハッシュ（MD5/SHA1/SHA256）が公開済み

【推奨アクション】
・BYOVD 対策としてWindowsのドライバブロックリスト（Microsoft脆弱ドライバブロックリスト）を最新状態に維持し、カーネルモードドライバのコード署名ポリシーを強化する
・Windows Event ID 7045（新規サービスインストール）をリアルタイム監視し、Kaspersky・Valorant・WatchDog・Javelin 等の名称を持つ不審サービスを即時調査する
Splunk SPL: index=windows EventCode=7045 | eval suspicious=if(match(ServiceFileName,"(?i)(nal\.sys|dbutil_2_3\.sys|procexp152\.sys|WinRing0x64\.sys|mhyprot2\.sys|nal_w10\.sys|rtkio64\.sys)"),1,0) | where suspicious=1 | table _time, host, ServiceName, ServiceFileName
→ 既知の脆弱ドライバファイル名に一致するサービスが登録された場合はインシデント宣言のトリガーとして扱う
Splunk SPL: index=windows EventCode=7045 | where match(ServiceName,"(?i)(kaspersky|valorant|javelin|watchdog|gentl)") | table _time, host, ServiceName, ServiceFileName, AccountName
→ 偽装名称のサービス登録は GentleKiller バリアントの特徴であり、ホストを即時ネットワーク隔離する
