  ・ CVE-2026-54420 / LiteSpeed cPanel Plugin（2.4.8 未満）
    CVSS: 8.5（High）
    状態: KEV登録済み・実悪用確認・パッチあり

    【24時間以内の変化】

      [Security NEXT 2026-06-16]
        「LiteSpeed cPanel Plugin」に権限昇格の脆弱性 - すでに悪用も として国内報道。

      [CISA KEV 2026-06-15〜16]
        KEV カタログに追加。FCEB 機関の修正期限: 2026-06-18（48時間以内）。

    【概要】

      cPanel 上で動作する LiteSpeed Web Server プラグインの
      シンボリックリンク処理不備に起因する権限昇格の脆弱性。
      FTP 資格情報または Web シェルアクセスを持つ攻撃者が
      CloudLinux / CageFS のユーザー分離を回避し、root 権限を取得できる。
      共有ホスティングサービス上での多テナント侵害につながるリスクがある。
      悪用は少なくとも 2026年5月から観測されており、KEV 登録後にさらに攻撃が加速する可能性がある。

      攻撃の流れ:
        1. FTP 認証情報の侵害または Web シェルの設置（初期アクセス）
        2. 細工したシンボリックリンクを作成し、cPanel プラグインの内部 API を悪用
        3. CageFS の権限境界を突破して root に昇格

    【IoC】

      IoC: 確認されず（侵害指標の公開なし）

    【監視ポイント】

      ・ [cPanel / LiteSpeed ログ]  root 権限での予期しないファイル操作・
        ユーザー切り替えイベントを確認する
      ・ [ホスティング管理ログ]  FTP アクセス後に root レベルの操作が
        実行された痕跡を探す

    【参照】

      https://thehackernews.com/2026/06/cisa-flags-litespeed-cpanel-plugin-flaw.html
      https://securityaffairs.com/193684/security/u-s-cisa-adds-cisco-catalyst-and-litespeed-cpanel-plugin-flaws-to-its-known-exploited-vulnerabilities-catalog.html

  ・ CVE-2026-20262 / Cisco Catalyst SD-WAN Manager（複数バージョン）
    CVSS: 6.5（Medium）
    状態: KEV登録済み・実悪用確認（限定的）・パッチあり

    【24時間以内の変化】

      [Security NEXT 2026-06-16]
        「Cisco Catalyst SD-WAN Manager」に脆弱性 - 侵害有無の確認を として国内報道。

      [Cisco / CISA 2026-06-15〜16]
        Cisco がセキュリティアドバイザリを公開。CISA が KEV に追加。
        修正期限: 2026-06-29。Cisco は IOC を共有して管理者に調査を要請。

    【概要】

      SD-WAN Manager の Web UI でファイルアップロード時のパス検証が
      不十分であることを利用する脆弱性。
      認証済みの攻撃者が細工した HTTP リクエストを送信し、
      任意のファイルを作成・上書きすることで最終的に root へ昇格できる。
      Cisco の内部テストで発見され、その後限定的な悪用が確認された。
      SD-WAN 管理コンソールがインターネットに露出している場合は優先対処が必要。

      攻撃の流れ:
        1. 有効な認証情報（書き込み権限以上）でログイン
        2. 細工した HTTP リクエストでパス外のファイルを上書き
        3. index.jsp または .war ファイルを設置して root 権限でコード実行

    【IoC】

      ログ監視対象（Cisco 推奨）:
        ・ vmanage-server ログ内の index.jsp / .war アップロード試行
        ・ vmanage-appserver および serviceproxy-access ログの異常

    【監視ポイント】

      ・ [SD-WAN Manager 管理ログ]  未知の .jsp / .war ファイルのアップロード、
        予期しない root 実行コンテキストを確認する
      ・ [ネットワーク境界]  管理 UI（デフォルトポート 443 / 8443）への
        インターネット直接露出を確認し、アクセス制限を徹底する

    【参照】

      https://www.helpnetsecurity.com/2026/06/16/cisco-sd-wan-cve-2026-20262-exploited/

  ・ Velvet Ant（中国帰属、信頼度: 中）/ Operation Highland
    採用契機: R（新規マルウェア: PAMモジュール・OpenSSH改ざん）、S（新規TTP）、V（重要組織侵害）
    帰属信頼度: 中（Sygnia 単一ベンダーレポート、中国nexusとの状況証拠）

    Sygnia が 2026年6月15日前後に「Operation Highland」として公表。
    2016年から2026年まで約10年間、大規模組織の「エアギャップ」内部ネットワークに
    気づかれずに潜伏していたことが判明した。
    攻撃者は PAM モジュール 9 種類と OpenSSH バイナリを改ざんし、
    認証スタック自体をバックドア化することで全ログインの可視化を維持。
    過去に Sygnia が 2024年に公表した F5 BIG-IP 悪用キャンペーン（3年間潜伏）
    とも同一グループと推定される。

    主要 TTP:
      ・ [T1556.003]  PAM モジュール改ざん — 認証時の資格情報傍受
      ・ [T1554]  クライアント製品への感染 — トロイの木馬 OpenSSH バイナリ
      ・ [T0869 相当]  内部 C2 — レガシーファイルサーバを C2 として流用
      ・ [T1078.004]  複数フットホールドの確保 — レガシー・未監視機器を重点的に感染

    推奨アクション:
      ・ PAM モジュール（/lib/security/*.so, /etc/pam.d/* 等）のハッシュを
        既知のクリーン版と比較検証する
      ・ OpenSSH バイナリの改ざん検知（AIDE / Tripwire 等）を実施する
      ・ レガシー・EOL サーバをネットワークセグメントから隔離し、
        モニタリング対象に加える
      ・ エアギャップ環境の端末でも EDR / FIM 導入を検討する

    参照: https://www.sygnia.co/blog/operation-highland-velvet-ant/
          https://www.helpnetsecurity.com/2026/06/15/velvet-ant-backdoored-authentication-persistence/
          https://www.darkreading.com/cyberattacks-data-breaches/china-velvet-ant-apt-multiyear-espionage


  ・ 不明（帰属未確定）/ "Atomic Arch" — AUR サプライチェーン攻撃
    採用契機: P（新規キャンペーン）、R（新規マルウェア: eBPF ルートキット + インフォスティーラー）
    帰属信頼度: 低（帰属未確定）

    2026年6月11〜12日に発覚した Arch Linux AUR（ユーザーリポジトリ）への
    大規模サプライチェーン攻撃。確認されたパッケージ数は最終的に 1,500 件超。
    攻撃者はメンテナ不在の孤立パッケージを正規手続きで取得し、
    PKGBUILD スクリプトを改ざん。npm パッケージ atomic-lockfile / js-digest 経由で
    eBPF ルートキットとインフォスティーラーを配布した。
    公式 Arch Linux リポジトリへの感染は確認されていないが、
    yay / paru 等の AUR ヘルパーを使用する Linux エンジニア・開発者環境が対象。
    日本国内でも Arch Linux ベースの開発環境や WSL 環境で
    AUR を使用している場合はパッケージ更新ログの確認が必要。

    検知ツール:
      GitHub: https://github.com/lenucksi/aur-malware-check

    推奨アクション:
      ・ AUR ヘルパーのインストール / アップグレードログを過去 2 週間分確認する
      ・ atomic-lockfile / js-digest パッケージの存在を確認し、検出時は隔離する
      ・ eBPF プログラムのロード一覧（bpftool prog list 等）に不審なエントリがないか確認する
      ・ SSH 秘密鍵・アクセストークンを確認し、侵害疑いがあれば無効化・ローテーションする

    参照: https://www.securityweek.com/atomic-arch-supply-chain-attack-hits-1500-aur-packages/
          https://latesthackingnews.com/2026/06/13/aur-supply-chain-attack-arch-packages-backdoored/
          https://www.stepsecurity.io/blog/400-aur-packages-hijacked-atomic-arch-campaign/
