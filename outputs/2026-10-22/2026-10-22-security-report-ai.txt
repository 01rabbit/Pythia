AI-2026-10-22-001 LiteLLM 1.107.0 の PyPI／Docker 配布物が侵害され資格情報窃取・バックドアを配布（エンジニア3人の GitHub アカウント経由・攻撃者の特定なし）
------------------------------------------------------------
カテゴリ: C/C6 / 軸X=8 軸Y=7
被害規模: PyPI の LiteLLM 1.107.0 wheel（Windows／macOS／Linux 各種）と Docker イメージが対象。パッケージは隔離・悪意ある Docker イメージは削除済み。被害件数・感染数は未公表。

【24時間以内の変化】
[The Hacker News（StepSecurity 引用） 2026-10-21] LiteLLM の director of security が、3人のエンジニアの GitHub アカウント（GitHub CLI の OAuth トークン窃取の可能性）で悪意ある版が公開されたと説明。

【概要】
THN によれば、LiteLLM 1.107.0 の wheel に cook.pth（import cook を Python 起動時に自動実行）が含まれ、資格情報窃取機能（StepSecurity 命名 privcollect：クラウド資格情報・秘密鍵・ブラウザデータ・AI ツール認証ファイル・環境変数・LiteLLM プロキシ設定を収集し HTTP POST で送信）と、GitHub のデッドドロップを1時間ごとに確認して Python コードを実行するバックドアを持つ。THN は特定の攻撃者に帰属しておらず、3月の TeamPCP 関連の LiteLLM 侵害と起動挙動が同じと記すのみ（同一主体とは明示していない）。LiteLLM は関係トークンを失効し、未確認の追加アクセスの可能性は排除できていない。

【攻撃フロー】
1. エンジニア3人の GitHub アカウント（窃取した OAuth トークンの可能性）で release ワークフローを起動・承認
2. 悪意ある wheel／Docker イメージを PyPI／レジストリへ公開
3. インストール後 cook.pth 経由で資格情報窃取とバックドアが起動

【監視】
Python の site-packages における cook.pth の出現、litellm[.]dev への HTTP POST、GitHub のデッドドロップへの定期的アクセスを監視する。

【参照】
- LiteLLM Compromised in Supply Chain Attack Delivering Credential Stealer and Backdoor (The Hacker News) https://thehackernews.com/2026/10/litellm-compromised-in-supply-chain.html

------------------------------------------------------------
カテゴリ: A/A4 / 軸X=6 軸Y=4
被害規模: インドの大学サイトへのブルートフォース（1件で有効なログインを確認）、別大学の MongoDB から 5,200 件超の学生・教職員 PII を持ち出し。他は計画・準備段階（VoIP 詐欺・暗号資産保有者の偵察）。

【24時間以内の変化】
[Unit 42 2026-10-21] Unit 42 が BUGSTER（金銭目的・英語話者・過去の報告なし）の AI 支援犯罪活動の分析を公表。

【概要】
Unit 42 によれば、BUGSTER は Hermes Agent フレームワーク（推論エンジンに DeepSeek V4・Telegram で制御・システムプロンプトの上書きで安全制御を無効化）と、権限・サンドボックス制御を回避する設定の Cursor IDE を用い、侦察・ブルートフォース・DB 窃取・EC サイトの API トークン抽出・WPA ハンドシェイクのクラウド GPU 解析・Python 製 C2 リスナー（Windows リバースシェル）・Go 製の資格情報スキャナーを実行した。基本的なツールに AI 生成のスクリプトを組み合わせて実害を出した、と評価している。Unit 42 は複数の無関係な攻撃者が同じ Hermes＋DeepSeek の組み合わせを採用していると記す。
