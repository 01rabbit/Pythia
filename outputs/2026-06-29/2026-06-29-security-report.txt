1. Djinn Stealer: CVE-2026-48558 悪用による AI 開発者認証情報・MCP コンフィグ窃取
カテゴリ: C（AI インフラ攻撃）/ サブカテゴリ: C3（MCP サーバー・エージェント統合基盤の認証情報窃取） / 攻撃者種別: 犯罪組織
------------------------------------------------------------

採用契機: Q（実際のインシデント・被害報告）・R（AI セキュリティ CVE 関連の実害）
MITRE ATLAS: ATLAS TTP: 詳細未公開（新規攻撃パターン・分類調査中）
OWASP: 調査中
対象: IT・専門サービスセクター / グローバル / SimpleHelp 経由の AI 開発者エンドポイント
被害規模: 14,000 台以上の SimpleHelp サーバーが潜在的露出対象。AI 開発者認証情報の窃取被害組織数は不明（調査継続中）

【24時間以内（または期間内）の変化】
[BleepingComputer 2026-06-29] CVE-2026-48558 悪用で展開される Djinn Stealer が Claude・Gemini・Codex・Cline・OpenCode・Kilo 等の AI コーディングアシスタントの設定ファイルと MCP サーバー設定を標的とすることが初報

【概要】
Djinn Stealer は CVE-2026-48558（SimpleHelp OIDC 認証バイパス・CVSS 10.0）を悪用してエンドポイントに展開される新規のクロスプラットフォーム型インフォスティーラーで、AI 開発者の認証情報と MCP（Model Context Protocol）コンフィグファイルを主要標的とする。Windows・macOS・Linux に対応し、Claude・Gemini・Codex・Cline・OpenCode・Kilo 等の AI コーディングアシスタントの設定ファイル（API キーを含む）・MCP サーバー設定・SSH 秘密鍵・AWS/GCP/Azure のクラウドプロバイダー認証情報・Docker シークレット・Terraform 設定ファイルを収集する。窃取された AI API キーは LLMjacking（被害者コストでの不正 API 利用）または AI システムへの不正アクセスに転用される可能性がある。MSP・IT サービス事業者の SimpleHelp 展開環境を経由することで、顧客組織の AI 開発環境が広範に侵害される。バースト検出: 3 件（BleepingComputer・Horizon3.ai・HelpNetSecurity）→ threshold_met。

攻撃の流れ:
1. 攻撃者は CVE-2026-48558 を悪用して SimpleHelp サーバーに認証なしでテクニシャン権限でログインする
2. テクニシャン権限で接続中のエンドポイントに Djinn Stealer を展開し、AI ツール設定ファイル（~/.claude/config.json・Cline/OpenCode 設定・MCP コンフィグ）・SSH キー・クラウド認証情報を網羅的に収集する
3. 収集した認証情報を C2 へ送信し、窃取した AI API キーを LLMjacking または標的組織の AI システムへの継続的不正アクセスに悪用する

【ATLAS TTPs】
ATLAS TTP: 詳細未公開（MCP コンフィグ窃取を用いた AI インフラ侵害は新規攻撃パターン。MITRE ATLAS へのケーススタディ申請を検討中）

【IoC / 検知シグナル】
IoC: 確認されず（ハッシュ・C2 IP は本稿時点で非公開）
検知シグナル: AI ツール設定ディレクトリ（~/.claude/・~/.config/claude/ 等）への異常な読み取りアクセス（複数ファイルを短時間に一括スキャン）
検知シグナル: SSH キーディレクトリ（~/.ssh/）の秘密鍵ファイルへのアクセス（プロセスが ssh-agent 以外の場合）
検知シグナル: クラウド認証情報ファイル（~/.aws/credentials・~/.config/gcloud/）へのアクセスが通常のアプリケーション以外のプロセスから発生

【監視・対策ポイント】
・[EDR / ファイル整合性監視（FIM）] AI 設定ファイルへの異常アクセスを検知する
Splunk SPL: index=endpoint_logs (file_path="*/.claude/*" OR file_path="*/.ssh/id_*" OR file_path="*/.aws/credentials*" OR file_path="*/mcp*.json") NOT process_name IN ("claude","ssh-agent","aws") | stats count by host, process_name, user, file_path | where count > 5
→ AI ツール設定・SSH キー・クラウド認証情報への正規プロセス以外からの一括アクセスは Djinn Stealer 活動の指標。SimpleHelp ログと照合して侵入経路を確認する
・SimpleHelp を v5.5.16 以上へ即時アップグレードする（CVE-2026-48558 の根本対策）
・侵害が疑われる AI API キー・クラウド認証情報・SSH キーを即時ローテーションする
・MCP サーバー設定ファイルの権限を 600 に設定し、不要な読み取りアクセスを制限する

1. CVE-2026-48558 / SimpleHelp Remote Support Software
対象: v5.5.15 以下（OIDC 認証を有効化した構成）
------------------------------------------------------------

優先度: 緊急
CVSS: 10.0 (Critical)
状態: 実悪用確認 / PoC 公開
パッチ: v5.5.16 リリース済み（即時適用必須）

【24時間以内の変化】
[BleepingComputer 2026-06-29] CVE-2026-48558 悪用によるDjinn Stealerの展開が確認。AI開発者認証情報・MCPコンフィグファイル・クラウドAPI認証情報を標的とする新型インフォスティーラー。
[Horizon3.ai 2026-06-29] OIDC認証バイパスのPoCを公開。CVSSv3 10.0 確定。
[HelpNetSecurity 2026-06-29] SimpleHelpがv5.5.16パッチをリリース。14,000台以上のSimpleHelp サーバーがインターネット上に露出。

【概要】
SimpleHelp リモートサポートソフトウェア v5.5.15 以下に CVSSv3 10.0 の認証バイパス脆弱性が発見され、2026-06-29 に実悪用が確認された。OIDC 認証が有効な環境において攻撃者は任意のテクニシャンアカウントとして認証なしでログイン可能（CWE-287）。攻撃者はこの脆弱性を悪用して Djinn Stealer を展開し、Claude・Gemini・Codex・Cline・OpenCode・Kilo 等の AI コーディングアシスタント設定ファイル・MCP コンフィグ・SSH キー・クラウドプロバイダー認証情報・Docker シークレット・Terraform 設定を窃取する。Windows・macOS・Linux のクロスプラットフォームに対応。14,000 台以上の SimpleHelp サーバーがインターネット上に露出しており、MSP・IT サービス事業者の顧客環境が広範に危険にさらされている。

攻撃の流れ:
1. OIDC 設定を持つ SimpleHelp v5.5.15 以下の /api/authenticate エンドポイントへ細工したリクエストを送信し、認証バイパスにより任意のテクニシャンアカウントでセッションを確立する
2. 取得したテクニシャン権限を使用してターゲットエンドポイントに Djinn Stealer を展開し、AI 開発ツール設定ファイル・SSH 秘密鍵・クラウド API キー・MCP サーバー設定・Docker シークレット・Terraform 認証情報を収集する
3. 窃取した認証情報を C2 サーバーへ外部送信し、AI API キーを悪用して LLMjacking またはクラウドインフラへの横展開を実施する

【暫定緩和策】
・SimpleHelp を v5.5.16 以上へ即時アップグレードする
・アップグレードが即時困難な場合は OIDC 認証機能を一時的に無効化する
・SimpleHelp 管理コンソールで全テクニシャンアカウントを監査し、未知の OIDC 経由セッション・不審なアカウントを削除する
・エンドポイント上の AI ツール設定ファイル（.claude/config.json・cline/settings.json・.ssh/id_* 等）・クラウド認証情報ファイルを確認し侵害の痕跡を調査する
・ネットワーク監視で SimpleHelp ポート（TCP 443/80）から外部への大量データ送信がないか確認する

【IoC】
IoC: 確認されず（Djinn Stealer ハッシュ・C2 IP は本稿時点で非公開）

【監視ポイント】

Splunk SPL: index=simplehelp_logs action=login auth_method=oidc | stats count by user, src_ip | where count > 3
→ 短時間での OIDC 認証試行増加または未知ユーザーでの OIDC ログイン成功は即時対応を開始する
Splunk SPL: index=endpoint_logs (file_path="*/.claude/config*" OR file_path="*/.ssh/id_*" OR file_path="*/.aws/credentials*") action=read | stats count by host, user, file_path | where count > 10
→ AI 設定ファイルへの大量アクセスは Djinn Stealer のスキャン活動を示す

活動タイプ: 新規マルウェア / 実活動キャンペーン

標的: 外交機関・政府機関・ソフトウェア開発企業 / インドネシア・台湾・香港・レバノン・シリア・コロンビア・北マケドニア・ネパール・セルビア

【24時間以内の変化】
[Kaspersky GReAT 2026-06-24] 初報: SharkLoader カスタムドロッパーを使用した新規中国語話者系 APT キャンペーンを詳細技術分析とともに公開
[The Hacker News 2026-06-26] インドネシア・台湾・香港等の外交・政府機関への広範なキャンペーン展開を報道

【概要】
Kaspersky GReAT が 2026-06-24 に公開した分析によると、中国語話者系 APT（帰属信頼度: 低）が新規カスタムドロッパー SharkLoader と Cobalt Strike Beacon を組み合わせた諜報活動キャンペーンを展開している。初期侵入には CVE-2021-26855（Exchange Server SSRF）・CVE-2023-32315（Openfire 認証バイパス）・CVE-2024-36401（GeoServer RCE）を悪用。SystemSettings.dll を DLL サイドローディングにより実行し、SharkLoader が Cobalt Strike Beacon をメモリ上で展開する。ポスト侵害では LSASS ダンプ・NTDS 抽出による認証情報窃取、FScan を用いた内部ネットワークスキャン、Searchall・Pillager による機密ファイル探索を実施。標的はインドネシア外交機関・台湾政府機関・香港/レバノン/シリア/コロンビア/北マケドニア/ネパール/セルビアのソフトウェア開発会社に及ぶ。

攻撃の流れ（判明分）:
1. インターネット公開されたサーバー（Exchange・Openfire・GeoServer）に CVE-2021-26855/CVE-2023-32315/CVE-2024-36401 を悪用して初期アクセスを確立する
2. SystemSettings.exe をおとりとして起動し、同ディレクトリに配置した悪意ある SystemSettings.dll を DLL サイドローディングで実行。SharkLoader が Cobalt Strike Beacon をメモリ内に展開し永続化する
3. LSASS ダンプ・NTDS 抽出で認証情報を大量取得し、FScan/Searchall/Pillager で内部偵察を実施。機密文書・外交通信・知的財産を C2 へ外部送信する

Cisco Unified Communications Manager（UCM）の CVE-2026-20230 に対する CISA FCEB 期限（連邦民間行政府機関の対応期限）が 2026-06-28 に経過した。FCEB 機関は昨日時点でパッチ適用が完了している必要があるが、残存する未パッチ環境でウェブシェルの設置等の持続的侵害が発生している可能性がある。/platform-services/axis2-web/ パスへの不審なアクセス確認が推奨される。

【推奨アクション】
・Cisco UCM のパッチ適用状況を確認し、FCEB 期限（2026-06-28）までに適用できなかった場合は即時適用する
・/platform-services/axis2-web/ パスへのアクセスログ（6 月 15 日以降）を調査し、不審なウェブシェルアクセスを確認する
・Cisco UCM の管理コンソールで未知のアカウント・サービスの作成が行われていないか確認する
・[Cisco UCM Web アクセスログ] axis2-web パスへのアクセスを確認する
Splunk SPL: index=cisco_ucm_logs request_path="*/axis2-web/*" NOT user IN ("admin","ccmadmin") | stats count by src_ip, request_path, user | sort -count
→ axis2-web パスへの管理者以外からのアクセスはウェブシェルの設置・利用を示す可能性がある
