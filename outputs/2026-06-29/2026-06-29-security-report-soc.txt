1. SimpleHelp CVE-2026-48558: OIDC 認証バイパス緊急パッチ適用と侵害確認
観点: ゼロデイ関連
採用契機: β（国内企業・組織が広く利用するサービスへの影響）・γ（SOC 運用に直接関係）・η（リモートサポートソフトウェアの脆弱性）
------------------------------------------------------------

優先度: 高
対象: SimpleHelp Remote Support Software（v5.5.15 以下・OIDC 有効構成）

【24時間以内の変化】
[BleepingComputer / Horizon3.ai 2026-06-29] CVE-2026-48558 実悪用確認・Djinn Stealer 展開・v5.5.16 パッチリリース。14,000 台超露出中。

【概要】
SimpleHelp の OIDC 認証バイパス脆弱性（CVE-2026-48558・CVSS 10.0）が実悪用され、Djinn Stealer が展開されている。MSP・IT サービス事業者が SimpleHelp を使用している場合、顧客環境の AI 開発者認証情報・クラウド認証情報が広範に侵害される可能性がある。今日中の対応が必須。

【推奨アクション】
・SimpleHelp を v5.5.16 以上へ即時アップグレードする（最優先）
・アップグレードが即時困難な場合は OIDC 認証を一時的に無効化し、通常の認証方式に切り替える
・SimpleHelp 管理コンソールで全テクニシャンアカウントを監査し、OIDC 経由で作成された不明アカウントを削除する
・SimpleHelp に接続した全エンドポイントで AI ツール設定ファイル・SSH キー・クラウド認証情報の侵害確認を実施する（~/.claude/config.json・~/.aws/credentials・~/.ssh/id_* 等）
・侵害が疑われる AI API キー・クラウド認証情報・SSH キーを即時ローテーションする
・[SimpleHelp 管理ログ / EDR ログ] OIDC 経由の不審ログインを監視する
Splunk SPL: index=simplehelp_logs action=login auth_method=oidc | stats count by user, src_ip, _time | where count > 3
→ 未知ユーザーでの OIDC ログイン成功は即時対応を開始する

【参照】
https://www.bleepingcomputer.com/news/security/simplehelp-cve-2026-48558-oidc-bypass-djinn-stealer/

2. Oracle EBS CVE-2026-46817: 実悪用確認による C2 ブロックと CSPU 適用確認
観点: CVE関連
採用契機: β（国内企業が広く利用する Oracle EBS への影響）・δ（海外で話題・国内波及近い）
------------------------------------------------------------

優先度: 高
対象: Oracle E-Business Suite (EBS) 12.2.3〜12.2.15

【24時間以内の変化】
[BleepingComputer / CybersecurityNews 2026-06-28] CVE-2026-46817 実悪用開始を確認。C2 IP 45.84.137.125 を特定。Oracle EBS 12.2.3〜12.2.15 が対象。

【概要】
Oracle EBS（Oracle Payments / File Transmission モジュール）の CVE-2026-46817（CVSS 9.8）が 2026 年 6 月 27〜28 日から実悪用されている。2026 年 5 月の CSPU で修正済みだが未適用の組織が標的となっている。C2 IP 45.84.137.125 が確認されており、財務データ・支払い情報の窃取が主要目的とみられる。Oracle EBS を外部に公開している組織は今日中に C2 ブロックとパッチ適用状況の確認が必要。

【推奨アクション】
・ファイアウォールで C2 IP アドレス 45.84.137.125 をブロックする（インバウンド・アウトバウンド両方）
・2026 年 5 月 CSPU（Critical Patch Update Supplement）の適用状況を確認し、未適用の場合は即時適用する
・Oracle EBS Web サーバーのアクセスログで /OA_HTML/ibytransmit エンドポイントへの POST リクエストを 6 月 27 日以降に遡り確認する
・追加 IOC 公開を Mandiant/CrowdStrike/Trend Micro で監視し IOC リストを更新する
・[Oracle EBS Web サーバーログ / ネットワークフロー] 悪用エンドポイントへのアクセスと C2 通信を監視する
Splunk SPL: index=network_logs (dest_ip="45.84.137.125" OR src_ip="45.84.137.125") | stats count by src_ip, dest_ip, dest_port | sort -count
→ C2 IP との通信を検知した場合はただちにインシデント対応を開始する

【参照】
https://www.bleepingcomputer.com/news/security/oracle-ebs-cve-2026-46817-active-exploitation/

3. TraderTraitor DeFi サプライチェーン攻撃: DeFi プロジェクト開発者向け npm 依存関係監査
観点: APT関連
採用契機: α（当該 APT による標的業種への直接影響）・ζ（重要情報漏えいリスク）
------------------------------------------------------------

優先度: 高
対象: DeFi / ブロックチェーンプロジェクト（npm 依存パッケージ）

【24時間以内の変化】
[Chainalysis / FBI 2026-06-28] TraderTraitor（Lazarus Group/DPRK）が KelpDAO・DriftUK の DeFi スマートコントラクトを改ざん。npm サプライチェーン侵害経由。FBI が高信頼度で帰属確認。

【概要】
DPRK 国家支援グループ TraderTraitor が DeFi プロジェクトの npm 依存パッケージを侵害しスマートコントラクトを改ざんする攻撃を確認。DeFi・ブロックチェーン・暗号資産関連の開発環境に携わる組織は npm 依存関係の完全性確認を即時実施する必要がある。

【推奨アクション】
・npm audit・Snyk・Dependency-Track で全依存パッケージの完全性を確認する
・LinkedIn 経由の採用・コンサルティング接触に対し特別な警戒を実施する（TraderTraitor の典型的な接触手口）
・スマートコントラクトの最終デプロイコードと正規ソースコードの整合性を検証する
・npm パッケージの postinstall スクリプトを確認し予期しない外部通信がないか調査する
・[npm インストールログ / CI/CD パイプライン実行ログ] postinstall の外部通信を監視する
→ npm postinstall による予期しない外部 HTTP リクエストは即時調査対象

【参照】
https://www.chainalysis.com/blog/tradertaitor-kelpdao-driftuk-2026/
https://www.fbi.gov/news/press-releases/tradertaitor-dprk-defi-campaign-2026

4. LiteLLM CVE-2026-42271: SSRF 脆弱性対応とアクセス制御強化
観点: AI攻撃関連
採用契機: η（AI インフラの重大脆弱性）
------------------------------------------------------------

優先度: 高
対象: LiteLLM 1.42.0 以下

【24時間以内の変化】
[GitHub Security Advisory / SecurityWeek 2026-06-28] CVE-2026-42271（CVSS 9.1・SSRF）の PoC が公開。LiteLLM 1.43.0 パッチリリース済み。

【概要】
LiteLLM v1.42.0 以下の SSRF 脆弱性（CVE-2026-42271）の PoC が公開された。AI ゲートウェイ経由での内部ネットワーク偵察・クラウドメタデータ窃取が可能。LiteLLM を外部公開している組織は今日中の対応が必要。

【推奨アクション】
・LiteLLM を 1.43.0 以上へ即時アップグレードする
・外部公開の LiteLLM インスタンスを特定し WAF で保護またはアクセス制御を強化する
・内部メタデータエンドポイント（169.254.169.254 等）へのアクセスログを確認する
・LiteLLM のリクエストログで内部 IP・メタデータエンドポイントへの不審なアクセスを監視する
→ LiteLLM から内部 IP への HTTP リクエストは即時調査対象

対象: メール / ドキュメント（外交・首脳会談テーマ）
