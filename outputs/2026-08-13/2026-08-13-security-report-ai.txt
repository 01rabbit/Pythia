1. LiteLLM/Trivy侵害サプライチェーン攻撃 - CloudSEKが2,500組織超の露出を確認
カテゴリ: C / サブカテゴリ: C6 / 攻撃者種別: 不明
------------------------------------------------------------

採用契機: A-Q / A-U
MITRE ATLAS: 該当タクティクスなし / 調査中
OWASP: 該当項目の明示なし
対象: it / manufacturing / telecom / global
被害規模: CloudSEK確認: 約434,000件の窃取ファイル・イベントを分析し2,500組織超の露出を確認（NVIDIA・Cisco・Deloitte・Volkswagen・FedEx・Siemens・X Corp等の名前を含むデータセット公開。ただし露出=確認済み侵害ではない点にCloudSEKも留意を促している）
独立ソース数: 2件（below_threshold）

【24時間以内の変化】
[The Hacker News 2026-08-12] CloudSEKが、2026年3月のAqua Security Trivy侵害経由で流出したPyPIトークンを用いてLiteLLM 1.82.8へ悪意あるコードが混入された事案（PyPI滞在約40分・2026-03-24 10:39〜16:00 UTC）について、約434,000件の窃取ファイル・イベント分析に基づき2,500組織超の露出を確認したと報告。悪意あるバージョンには`litellm_init.pth`というPythonインタプリタ起動時に自動実行されるファイルが含まれ、LiteLLMをインポートしなくても影響を受ける設計だったと新たに判明
[SecurityWeek 2026-08-12] CloudSEKが露出組織を名前・ドメインで検索できる公開データセット（exposure.cloudsek.com/ai-supply-chain-incident）を公開したと報道。以前は別々に語られていた複数の被害報告が「同一攻撃チェーンの異なる段階」であったことも整理された

【概要】
2026年6月19日付で既報のLiteLLM PyPIサプライチェーン侵害（Aqua Security Trivyの侵害を起点に窃取したPyPIトークンでLiteLLM 1.82.8へ悪意あるコードを混入、TeamPCPによる認証情報窃取・Vectランサムウェアとの連携）について、脅威インテリジェンス企業CloudSEKが2026-08-12、約434,000件の窃取ファイル・イベントの分析に基づき2,500組織超が露出したと報告した。技術的な新知見として、悪意あるバージョンにはPythonインタプリタ起動時に自動実行される`litellm_init.pth`ファイルが含まれ、LiteLLMを直接インポートしていない環境でも影響を受ける設計だったことが判明。CloudSEKは露出組織を検索できる公開データセットを提供し、NVIDIA・Cisco・Deloitte・Volkswagen・FedEx・Siemens・X Corp等の大企業名を含むが、リスト掲載は侵害の確定を意味しないと注記している。

攻撃の流れ:
1. 2026年3月、Aqua Security Trivyの侵害で漏洩したPyPI APIトークンを攻撃者が悪用
2. LiteLLM 1.82.8へ、Pythonインタプリタ起動時に自動実行される`litellm_init.pth`を含む悪意あるコードを混入しPyPIへ直接アップロード（滞在時間約40分）
3. ダウンロードした環境でクラウド鍵・SSH鍵・Kubernetesトークン・DBパスワード等の認証情報を窃取

【IoC / 検知シグナル】
IoC: 確認されず
検知シグナル: litellm_init.pth ファイルの存在（sitecustomize相当の自動実行ファイル）

【監視・対策ポイント】
・CI/CD環境・Python実行環境における`litellm_init.pth`ファイルの存在と2026年3月時点のLiteLLM 1.82.8導入履歴を確認する
Splunk SPL: index=file_integrity file_name="litellm_init.pth" | stats count by host,file_path
Splunk SPL: index=pip_install_logs package="litellm" version="1.82.8" | table _time,host
→ exposure.cloudsek.com/ai-supply-chain-incidentで自組織名・ドメインが該当しないか確認し、該当する場合は該当期間にLiteLLMを導入していたホストの認証情報を全面ローテーションする。
