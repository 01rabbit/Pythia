1. CVE-2026-67276 / MikroTik RouterOS（SSHサービス）
対象: 6.0.0〜6.49.20 / 7.0.0〜7.23.3 / 7.24〜7.24.1（修正版: 6.49.21・7.23.4・7.24.2・7.25beta3）
------------------------------------------------------------

優先度: 緊急（パッチ提供済み・侵害痕跡確認必須）
CVSS: 9.2 (Critical)
状態: 実悪用確認 / PoC公開 / ゼロデイ
パッチ提供: 提供済み（6.49.21 / 7.23.4 / 7.24.2 / 7.25beta3）

【24時間以内の変化】
[CERT Polska 2026-09-05] CERT.PL が CVE-2026-67276 を含む RouterOS 6件の脆弱性を公開し、同時に別記事で「実際の攻撃が少なくとも2026-09-02から観測されている」と実悪用を公表した。CVE-2026-67276 と CVE-2026-86060 を組み合わせた攻撃連鎖を CERT.PL は MikroTrick と呼称している。
[NVD 2026-09-06] CVE-2026-67276 が NVD へ新規公開（CNA: CERT-PL・CVSS v4.0 9.2 Critical・CWE-347）。
[Nick Pratley (npratley.net) 2026-09-04] RouterOS 7.23.4 の「サイレントパッチ」を逆解析した技術記事が公開され、RSA 署名偽造の実証コード forge_e3_ssh.py を含む複数の PoC が公開された。

【概要】
MikroTik RouterOS の SSH サーバが、認可済みユーザー鍵と SSH 認証要求を突き合わせる際に RSA 公開鍵を完全一致で比較せず、鍵種別とモジュラスのみを確認して指数（exponent）を無視していた。署名検証には「クライアントが提示した鍵」がそのまま使われるため、認可済みユーザーの RSA モジュラス（公開情報）を知る攻撃者は指数を1に差し替えた鍵を提示することで有効な署名を偽造でき、秘密鍵なしに当該ユーザーとして SSH コマンドチャネルを開ける。CVSS v4.0 9.2（AV:N/PR:N/UI:N）。CERT.PL は本脆弱性と CVE-2026-86060（SSH ログイン時の引数処理不備による権限昇格）を連鎖させる攻撃を MikroTrick と名付け、SSH が外部公開された機器に対して少なくとも2026-09-02から実際の攻撃が発生していること、攻撃者が認証なしで機器を完全に掌握していることを確認したと公表した。ベンダーは 2026-09-03 に技術詳細を伏せたまま修正版（6.49.21 / 7.23.4 / 7.24.2 / 7.25beta3）を全チャネルへ公開しており、実悪用の観測がベンダー公表・CVE 採番に先行している点でゼロデイ性が高い。侵害された機器は RouterOS のアップグレード時に「Flagged」状態としてログへ記録される。2026-09-06 時点で CISA KEV への登録は未確認、EPSS スコアは未算出（公開直後のため）。

攻撃の流れ:
1. インターネットへ露出した RouterOS の SSH ポート（既定 22/TCP）へ接続する。
2. 認可済みユーザーの RSA 公開鍵モジュラスを取得し、指数を1に置き換えた公開鍵を提示して署名を偽造、秘密鍵なしに当該ユーザーとして認証を通過する（CVE-2026-67276）。
3. 禁止文字で始まるユーザー名（CERT.PL 公表のログでは `-2`）を用いた SSH ログイン経路の引数処理不備により、RouterOS のポリシーマスクを書き換えて管理者権限へ昇格する（CVE-2026-86060）。
4. 機器を認証なしで完全掌握し、特権ユーザー（観測例では `ops`）の作成・スクリプト追加・設定改変を行う。

【暫定緩和策】
・6.49.21 / 7.23.4 / 7.24.2 / 7.25beta3 以降へ即時アップグレードする（アップグレード時に RouterOS が侵害判定を行い、該当機器を Flagged 状態にする）。
・パッチ適用までの間、SSH・HTTP/HTTPS・bandwidth-test サービスを無効化するか信頼済みネットワークからのみ到達可能に制限する（CERT.PL 推奨）。
・信頼できないネットワーク経由での TLS 接続の開始・RouterOS 内蔵 SSH クライアントの使用を避ける（CERT.PL 推奨）。
・パッチ適用後にログを侵害痕跡（`login failure for user -2 ... via ssh`）で確認し、未知のユーザー・スクリプト・設定変更の有無を棚卸しする。

【監視ポイント】
・RouterOS の syslog を SIEM へ集約し、CERT.PL が公表した侵害痕跡（禁止文字始まりユーザー名でのログイン失敗ログ・攻撃元IP・特権ユーザー ops の作成）と、外部から管理ポート（22/TCP 等）への到達を監視する
Splunk SPL: index=network sourcetype=mikrotik ("login failure for user -2" OR "login failure for user -") | rex field=_raw "from (?<src_ip>\\d+\\.\\d+\\.\\d+\\.\\d+) via ssh" | stats count values(src_ip) as src_ip by host
Splunk SPL: index=network sourcetype=mikrotik src_ip IN ("82.192.72.4","103.102.31.18") | stats count earliest(_time) as first_seen latest(_time) as last_seen by host, src_ip
Splunk SPL: index=network sourcetype=mikrotik ("user added" OR "added user" OR "ops") | search "ops" | stats count by host, _time
→ `login failure for user -2 ... via ssh` は CERT.PL が公表した攻撃固有のログパターンであり、通常運用ではまず発生しない。検知した場合は攻撃試行そのものであり、成功可否に関わらず当該機器のユーザー一覧・スクリプト・スケジューラ・NAT/ファイアウォールルールを直ちに棚卸しする。公表IPは既知分のみのため、IP一致がないことを非侵害の根拠にしてはならない。

2. CVE-2026-86060 / MikroTik RouterOS（SSHログイン処理）
対象: 6.0.0〜6.49.20 / 7.0.0〜7.23.3 / 7.24〜7.24.1（修正版: 6.49.21・7.23.4・7.24.2・7.25beta3）
------------------------------------------------------------

優先度: 緊急（パッチ提供済み・侵害痕跡確認必須）
CVSS: 9.2 (Critical)
状態: 実悪用確認 / PoC公開 / ゼロデイ
パッチ提供: 提供済み（6.49.21 / 7.23.4 / 7.24.2 / 7.25beta3）

【24時間以内の変化】
[CERT Polska 2026-09-05] CERT.PL が CVE-2026-86060 を公開し、CVE-2026-67276 との組み合わせ（MikroTrick）による認証不要の完全掌握が2026-09-02以降実際に観測されていると公表した。侵害痕跡としてログ文字列 `login failure for user -2 from <ip> via ssh` と特権ユーザー ops の作成を提示。
[NVD 2026-09-06] CVE-2026-86060 が NVD へ新規公開（CNA: CERT-PL・CVSS v4.0 9.2 Critical・CWE-88）。
[Nick Pratley (npratley.net) 2026-09-04] ユーザー名 `-2` を用いた権限昇格の実証コード routeros_minus2_pty_poc.py が技術記事内で公開された。

【概要】
MikroTik RouterOS の SSH ログイン経路に、禁止文字で始まるユーザー名の引数処理不備（CWE-88 argument injection）があり、RouterOS が信頼するポリシーマスクを書き換えられて権限昇格に至る。悪用には未認証の SSH セッションが RouterOS のログインヘルパへ到達できることが必要であり、CVE-2026-67276（RSA 指数を無視した署名検証不備による SSH 認証バイパス）と連鎖することで、未認証の攻撃者が管理者権限で機器を完全掌握できる。CERT.PL はこの連鎖を MikroTrick と呼称し、SSH を外部公開した機器に対する実際の攻撃を少なくとも2026-09-02から観測したと公表している。CVSS v4.0 9.2。ベンダー修正版は2026-09-03公開の 6.49.21 / 7.23.4 / 7.24.2 / 7.25beta3。実証コードは2026-09-04公開の技術記事に含まれる。2026-09-06 時点で CISA KEV 未登録・EPSS 未算出。

攻撃の流れ:
1. CVE-2026-67276 等により未認証の SSH セッションを RouterOS のログインヘルパへ到達させる。
2. 禁止文字で始まるユーザー名（観測例では `-2`）を指定し、引数処理不備によって信頼済みポリシーマスクを書き換える。
3. 読み取り専用相当のセッションから管理者権限のコマンド実行へ昇格し、特権ユーザー作成・設定改変・スクリプト設置を行う。

【暫定緩和策】
・6.49.21 / 7.23.4 / 7.24.2 / 7.25beta3 以降へ即時アップグレードする。
・パッチ適用までの間、SSH を無効化するか信頼済みネットワークからのみ到達可能に制限する（CERT.PL 推奨）。
・アップグレード後に RouterOS の Flagged 状態とログを確認し、未知のユーザー（例: ops）・スクリプト・設定変更を棚卸しする。

【IoC】

IP: 103.102.31.18

【監視ポイント】
・RouterOS syslog における禁止文字始まりユーザー名でのログイン失敗、および直後の特権ユーザー作成・設定変更イベントを時系列で相関監視する
Splunk SPL: index=network sourcetype=mikrotik ("login failure for user -2" OR "login failure for user -") | rex field=_raw "from (?<src_ip>\\d+\\.\\d+\\.\\d+\\.\\d+) via ssh" | stats count values(src_ip) as src_ip by host
Splunk SPL: index=network sourcetype=mikrotik src_ip IN ("82.192.72.4","103.102.31.18") | stats count earliest(_time) as first_seen latest(_time) as last_seen by host, src_ip
Splunk SPL: index=network sourcetype=mikrotik ("user added" OR "added user" OR "ops") | search "ops" | stats count by host, _time
→ CVE-2026-67276 と同一の攻撃連鎖であるため検知観点は共通。ログイン失敗ログの直後に user/script/scheduler の追加イベントが続く場合は昇格成功の可能性が高く、機器の隔離と設定の完全な再構築を検討する。
