CVE-2026-119977 WordPress Core（アップグレード時のステージングパスを突く未認証 RCE）（CVSS 8.1・優先度 high・軸1=7 軸2=8）
------------------------------------------------------------
影響バージョン: WordPress 4.7〜7.1.3（修正版 7.1.4・2026-10-28 公開）
KEV: 収載 2026-11-03／悪用: 確認あり／PoC: 公開／修正: あり

【24時間以内の変化】
[CISA KEV（スイープの KEV カタログ 2026.11.03） 2026-11-03] CVE-2026-119977 が KEV に追加（dateAdded 2026-11-03・期限 11-06）。EUVD は悪用開始を 11-03 と記録。[新規]

【概要】
WordPress Core 4.7〜7.1.3 に、フルパッケージのコア更新時に使われる予測可能で Web から到達できるステージングパスが原因の未認証リモートコード実行がある（NVD／Wordfence CNA、CVSS 3.1 は 8.1・AC:H）。更新が行われる時間帯に未認証の攻撃者がコードを実行できる。修正版は 7.1.4（10-28）。CISA は 11-03 に KEV へ追加し、連邦機関の期限は 11-06。悪用の具体的な手口・規模を述べる一次報告は今回取得できていない。（推測）更新窓という条件のため、全サイトが常時危険という性質ではなく、自動更新が一斉に走る運用では露出が時間帯に集中しうる。

【攻撃フロー】
1. コア更新の実行時間帯に、予測可能なステージングパスへ未認証で到達する
2. 更新中の一時ファイルを介してサーバー上でコードを実行する（詳細な悪用手順の一次報告は未取得）

【暫定緩和策】
- WordPress を 7.1.4 以降へ更新する
- 更新が済むまで wp-content/upgrade/ への外部からのアクセスを Web サーバー側で遮断する（検索結果の解説記事に基づく）
- 自作・第三者のプラグイン更新機構がコア更新を経由しない場合は、予測可能な一時パスを使っていないか確認する

【検知】
コア更新の実行時間帯に wp-content/upgrade/ 配下へ届く外部からの HTTP リクエスト、更新直後に作られる未知の PHP ファイルを確認する。
CISA KEV 追加は 11-03（期限 11-06）。悪用の主体・件数・手法の一次報告は取得できておらず、KEV 追加事実のみが確認できる。WordPress 自身の勧告は重大度を Low としているとの二次情報があり、Wordfence CNA の 8.1 と評価が割れている。GitHub に PoC 名（wp2shell 系）が複数あるが、本 CVE との対応は未検証。

【参考情報】
- CVE-2026-119977: WordPress Core RCE https://www.rapid7.com/db/vulnerabilities/cve-2026-119977/
- WordPress Core 7.1.4 Fixes an Unauthenticated Upgrade-Window Race RCE https://www.rescana.com/post/wordpress-core-7-1-4-upgrade-staging-race-rce

【概要】
VulnCheck は、Siemens SIMATIC IoT2050 Advanced（Industrial OS 上の Node-RED）の認証欠如 CVE-2026-58115（CVSS 10.0）が悪用されていると明らかにした（THN）。未認証の遠隔攻撃者が最高権限でコードを実行できる。観測された活動は、悪意ある Node-RED フローによる wget／curl でのバイナリ取得（85.215.73[.]250 から取得し /dev/shm/.b で実行）、後続の 2 段階版（wget.sh を取得し 45.194.90[.]57:38472 のペイロードを /tmp/.kworker に保存）、任意コマンドを実行する HTTP バックドアフロー。Siemens の修正は 4.3.4.1 以降（勧告は 8 月）。SecurityWeek は同日に重大な Node-RED の欠陥が悪用されているとも報じたが、本文を取得できず同一 CVE かは未確認。

IoT2050 の Node-RED から wget／curl が走ること、/dev/shm/.b・/tmp/.kworker の作成、85.215.73[.]250 と 45.194.90[.]57:38472 への通信を確認する。
悪用は VulnCheck のハニーポットでの観測（2026-10-30 時点）。実環境での被害件数は記事に無い。KEV 収載の記載なし。
