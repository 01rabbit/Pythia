【概要】
LMCache は vLLM 等の LLM サーバを高速化する OSS の KV キャッシュ層で、キャッシュを独立サーバとして動かす multiprocess（distributed）モードでは、ワーカー登録用の ZeroMQ ROUTER ソケットが認証なしで公開される。CVE-2026-105192（JFrog 報告）は、このソケットに送られた msgpack メッセージの拡張コード1が DeviceIPCWrapper.Deserialize を経て pickle.loads に渡るため、単一の未認証 ZMQ DEALER メッセージで任意コード実行に至る（NVD 記載・CVSS 9.8）。The Hacker News は報道時点で修正版がないことを明記している。同日 VulnCheck 起点で、/run_script エンドポイントに投稿したスクリプトが FastAPI アプリオブジェクト経由で builtins を回復し OS コマンドを実行できる CVE-2026-107204（CVSS 9.8）と、全インターフェースで待ち受ける管理 HTTP エンドポイントの認証欠如により GET /env で環境変数の認証情報を読める CVE-2026-107206（CVSS 9.4）も公開された。実悪用・公開PoC・KEV 登録は本窓の取得情報にない。露出 AI 基盤を狙うクリプトマイニング活動（Section 1 の PoeLLM）が同窓で報じられており、未認証で到達可能な LMCache サーバは同種の自動スキャンの対象になり得る（推測）。

攻撃の流れ:
1. インターネットまたは内部ネットワークから、LMCache multiprocess モードの ZeroMQ ROUTER ソケット（または HTTP 管理エンドポイント）へ未認証で到達する
2. 拡張コード1を含む細工した msgpack メッセージを送り pickle.loads を誘発（CVE-2026-105192）、または /run_script に Python スクリプトを投稿（CVE-2026-107204）
3. LMCache プロセス権限で任意コード・OS コマンドを実行し、/env から取得した認証情報で横展開する（CVE-2026-107206・NVD 記載に基づく）

【暫定緩和策】
・multiprocess（distributed）モードを使用していない環境では無効のままとし、使用環境では ZeroMQ ソケットと HTTP 管理ポートをネットワーク層（セグメント分離・ファイアウォール・mTLS トンネル）で LLM ワーカーからのみ到達可能にする
・管理 HTTP サーバが 0.0.0.0 で待ち受ける既定設定を見直し、/env・/config・/run_script への外部到達を遮断する
・LMCache プロセスの環境変数に API キー・クラウド認証情報を置かない（置いている場合はローテーション対象として棚卸しする）
・修正版の公開を監視し、公開後は速やかに更新する
