AI-2026-10-25-001 LiteLLM 侵害の根本原因：2026-05-27 に公開リポジトリへ誤コミットされた Agent Platform のマスターキーが失効されず、10-10 から GitHub トークン窃取・リリース経路乗っ取りに悪用された
------------------------------------------------------------
カテゴリ: C/C6 / 軸X=8 軸Y=7
被害規模: 影響範囲は 10-22 の既報（PyPI の 1.107.0 と Docker Hub／GHCR のイメージ）と同一。被害件数は未公表。

【24時間以内の変化】
[The Hacker News（LiteLLM の公表） 2026-10-24] LiteLLM が侵害の時系列と根本原因を公表。マスターキー漏えい（2026-05-27）→ 10-10 に未失効キーで Agent Platform に侵入し GitHub CLI OAuth トークンを窃取 → 10-12 に第二のワークフローで広範な秘密情報を収集 → 10-21 にブランチ保護を上書きしリリース経路を類似名リポジトリへ向け 1.107.0 を公開。[既報・更新: 根本原因]

【概要】
THN によれば、LiteLLM は 2026-05-27 に公開リポジトリ LiteLLM-Labs/lite-harness へマスターキーを含む設定ファイルが誤ってコミットされ、force-push で履歴を上書きしたがキーを失効させなかったと説明した。攻撃者（未特定・IP 69.48.229[.]143）は 10-10 にこのキーで Agent Platform に入り、スコープが絞られていない組織オーナー相当の GitHub CLI OAuth トークンを取得、メンテナ 2 名のトークンを webhook.site へ送出した。承認端末の要件が「エンジニア 2 名の承認」に緩められていたため、盗んだ 2 つのトークンで起動と承認を行った。1.107.0 には Python 起動時に動く永続バックドア（毎時コード取得・実行）と、SSH・Git・環境変数・クラウド資格情報・ブラウザデータを litellm[.]dev/healthcheck へ送る窃取機能が含まれる（ドメイン登録は 10-13）。同社は関連トークンを全て失効中としている。

【攻撃フロー】
1. 公開リポジトリに誤コミットされた未失効のマスターキーで Agent Platform へ侵入
2. GitHub CLI OAuth トークン等を窃取し、承認要件が緩められたリリース経路を乗っ取り
3. 悪意ある 1.107.0 を PyPI／Docker Hub／GHCR へ公開し、導入環境の資格情報を窃取

【監視】
1.107.0 の導入有無と、導入環境の SSH 鍵・クラウド資格情報・パッケージレジストリトークンの不正利用を確認する。アプリ削除だけでは起動フックが残る可能性があるため site-packages を確認する。
