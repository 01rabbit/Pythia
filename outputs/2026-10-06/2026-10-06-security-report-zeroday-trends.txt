1. CVE-2026-88779 Citrix NetScaler ADC / NetScaler Gateway（バッファ境界の不適切な制限・DoS・CWE-119）（Citrix）
------------------------------------------------------------
優先度: high
CVSS v3: —  CVSS v4: —  KEV: 登録済み 2026-10-04  悪用: 確認  FCEB期限: 2026-10-07
影響バージョン: SAML SP/IdP として構成された NetScaler ADC / Gateway（修正版: 14.1-73.41以降・13.1-64.28以降・14.1-FIPS 14.1-73.41以降・13.1-FIPS/NDcPP 13.1-37.282以降）。具体的な影響範囲は Citrix CTX697174 を参照

【24時間以内の変化】
[The Hacker News / SecurityWeek 2026-10-05] Citrixが CVE-2026-88779（CVSS 8.7）を標的型ゼロデイ攻撃で悪用された脆弱性として修正版を公開したと報道。SAML SP/IdP 構成が条件で、DoS（SAML 展開のオフライン化）につながる。同製品で数日前に修正された CVE-2026-88771 / 88772 の悪用後に発生し、修正済み機器にも影響したとSecurityWeekが報じた。

【概要】
CVE-2026-88779 は NetScaler ADC / Gateway のメモリオーバーフロー（バッファ境界の不適切な制限）で、SAML サービスプロバイダ（SP）または IdP として構成された機器でサービス拒否につながる（CVSS 8.7）。Citrixは標的型のゼロデイ攻撃で悪用されたことを確認したと報じられ、CISA は 2026-10-04 に KEV へ追加済み（FCEB期限 2026-10-07・昨日既報）。報告者として Bishop Fox と watchTowr が挙げられている。THNによれば同製品の CVE-2026-88771 / 88772（Webシェル設置に悪用）の直後の脆弱性で、SecurityWeek は『数日前にパッチ適用した機器も影響を受けた』と報じる。データの完全性への影響は確認されていない。攻撃主体・標的規模・IOC は未公表で、3つのCVEが同一キャンペーンかは確認できていない（推測を含まない）。

【攻撃の流れ】
1. SAML SP/IdP 構成のNetScalerへ細工したリクエストを送りメモリオーバーフローを誘発しサービス拒否を起こす（報道に基づく・詳細手順は未公表）

【暫定対策】
・修正版（14.1-73.41 / 13.1-64.28 / FIPS・NDcPP 版 13.1-37.282 以降）へ更新する（CISA BOD 26-04: 期限2026-10-07）
・構成に 'add authentication samlAction'（SAML SP）または 'add authentication samlIdPProfile'（SAML IdP）が含まれるか確認し、該当機器を優先して更新する
・CVE-2026-88771 / 88772 の対応済みでも本件は別CVEのため追加更新が必要

【監視】
SAML 認証エンドポイントへの異常リクエスト、NetScaler プロセスの予期しない再起動・SAML 認証の突発的な失敗を確認する。悪用手法が未公表のため検知シグネチャは提供できない。

1. CVE-2026-61500 Rejetto HTTP File Server（HFS）3.0.0〜3.2.0（弱いPRNGによるセッションCookie署名鍵の予測→管理者セッション偽造→RCE）（Rejetto）
------------------------------------------------------------
優先度: high
CVSS v3: —  CVSS v4: 9.3  KEV: 未登録  悪用: 確認  FCEB期限: —
影響バージョン: HFS 3.0.0〜3.2.0（3.2.1で修正・2026年7月公開）

【24時間以内の変化】
[The Hacker News（VulnCheck引用）/ SecurityWeek / BleepingComputer 2026-10-05] VulnCheckが CVE-2026-61500 への悪用試行（小規模な偵察）を2026-10-01に確認したと報道。PoCは2026年9月下旬に公開済み。

【概要】
Rejetto HFS 3.0.0〜3.2.0 で、セッションCookieの署名鍵導出に弱い擬似乱数（Math.random()）が使われ、ログイン時に開示される乱数出力から生成器の状態を復元して管理者セッションを偽造できる（CVSS 9.3）。管理者権限を得ると server_code 設定機能経由で任意のJavaScriptを実行でき、RCEにつながる。THNによればAnthropicの『Mythos』AIモデルが発見し、2026年9月下旬にAlejandro Ramos氏がPoCを公開、VulnCheckが2026-10-01に中国テレコムのIPから米国・日本の公開HFSへの小規模な偵察を確認した。BleepingComputerは積極的なスキャンを報じる。CISA KEV未登録。同製品では CVE-2024-23692（CVSS 9.8）が2024年に悪用された前例がある。観測は『スキャン・悪用試行』であり、侵害成功の報告は未確認。

【攻撃の流れ】
1. 未認証でログイン処理から開示される乱数出力を収集し、PRNGの状態を復元してセッション署名鍵を予測
2. 管理者セッションCookieを偽造して管理インターフェースへアクセス
3. server_code 設定機能を利用して任意のJavaScriptを実行（RCE）

【ATT&CK】
・T1190 Exploit Public-Facing Application: インターネット公開のHFSに対する CVE-2026-61500 の悪用試行（VulnCheck報告）

【暫定対策】
・HFS を 3.2.1 以降へ更新する
・更新までHFSの管理インターフェースをインターネットへ公開しない（VPN・IP制限）
・HFSの server_code 設定と管理者セッションの利用履歴を確認する

【監視】
HFSのログインエンドポイントへの短時間・大量の連続リクエスト、予期しない管理者セッションと server_code 設定の変更を確認する。

1. Cling（ClingSTUN）ボットネットが Realtek Jungle SDK の CVE-2021-35394 等を悪用、STUNをC2チャネルに転用
------------------------------------------------------------
【24時間以内の変化】
[The Hacker News（Nozomi Networks引用）/ SecurityWeek 2026-10-05] ClingSTUN ボットネットの詳細分析を報道。

【概要】
Nozomi Networksは、Realtek Jungle SDKの重大な既知脆弱性 CVE-2021-35394（CVSS 9.8）の悪用を試みてボットネット『Cling』（FortinetはClingSTUNと呼称）を展開する活動を報告した。ルーターやDVRで永続化するバックドアで、STUNを正規のNAT越え通信に見せかけたC2に転用し、リモートトンネル・プロキシ・DoS・ワーム的拡散に対応する。Realtek・MVPower・Linksys・LB-LINK等の7件以上の脆弱性の悪用コードを内包する。2026-09-05頃から悪用が増加し10月も継続（報道）。SecurityWeekも同活動を報じた。

・SecurityWeek: Linux Backdoor Abuses STUN Protocol, Exploits Dozens of Flaws https://www.securityweek.com/linux-backdoor-abuses-stun-protocol-exploits-dozens-of-flaws
