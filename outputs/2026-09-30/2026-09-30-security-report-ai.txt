1. オランダDIVDが自律AIエージェントを用いた侵入を受ける（脆弱性悪用後の侵入活動をAIエージェントが自動実行）
カテゴリ: A/A4  軸X=7 軸Y=3  burst: 1（below_threshold）
------------------------------------------------------------

【24時間以内の変化】
[BleepingComputer 2026-09-30] DIVDがAI駆動のサイバー攻撃を受けたと報道。攻撃者は技術的脆弱性を悪用した後、自律AIエージェントに後続の侵入活動を実行させ、パスワードスプレー等を試みたが操作ミスで自らの攻撃活動を妨害した。

【概要】
脆弱性開示を担うオランダの非営利団体DIVDは、攻撃者が技術的脆弱性を突いた後に自律AIエージェントを展開し、後続の侵入活動を自動実行させたと公表した。エージェントは次の行動を自律的に判断して高速に動いたが、DIVDは「雑なロジック」で、パスワードスプレー等の試行では自己の攻撃活動を妨げる操作ミスもあったと説明する。攻撃者は未特定で、詳細は2026-10-01に公表予定とされる。単一報道ソースでの確認で、burstは閾値未満のため低優先度扱い。

【攻撃の流れ】
1. 技術的脆弱性を悪用して初期侵入
2. 自律AIエージェントが後続の侵入活動（パスワードスプレー等）を自動実行

【参照】
・BleepingComputer: Automated AI agent used to breach cybersecurity nonprofit DIVD https://www.bleepingcomputer.com/news/security/automated-ai-agent-used-to-breach-cybersecurity-nonprofit-divd

2. カスタムChatGPT（GPTs）を偽装しGoogleスポンサー広告経由でClickFix攻撃によりRATを配布
カテゴリ: A/A1  軸X=5 軸Y=3  burst: 2（below_threshold）
------------------------------------------------------------

【24時間以内の変化】
[BleepingComputer 2026-09-30] ChatGPTのカスタム版がGoogleスポンサー検索結果で宣伝され、ClickFix攻撃でマルウェアを配布する悪意あるサイトへ誘導していると報道。
[SecurityWeek 2026-09-29] 攻撃者がChatGPTのカスタムGPTをClickFix攻撃に利用していると報道。

【概要】
OpenAIのChatGPTのカスタム版がスポンサー検索結果で宣伝され、利用者を悪意あるサイトへ誘導してClickFix（利用者に貼り付け実行させる手口）でRATマルウェアを配布していると報じられた。マルウェア名・研究者名・被害規模は本窓の要約範囲では確認できていない。

【攻撃の流れ】
1. スポンサー検索結果でカスタムChatGPTを装う悪性サイトへ誘導
2. ClickFixにより利用者にコマンドを貼り付け実行させRATを導入

【参照】
・BleepingComputer: Custom ChatGPTs push ClickFix attacks to deploy RAT malware https://www.bleepingcomputer.com/news/security/custom-chatgpts-push-clickfix-attacks-to-deploy-rat-malware
・SecurityWeek: Hackers Use ChatGPT Custom GPTs in ClickFix Attacks https://www.securityweek.com/

3. 公式MCP Python SDKの欠陥により悪性MCPサーバがOAuth資格情報を窃取可能
カテゴリ: C/C1  軸X=4 軸Y=3  burst: 1（below_threshold）
------------------------------------------------------------

【24時間以内の変化】
[The Hacker News 2026-09-29] 公式MCP Python SDKの脆弱性で、悪性MCPサーバがクライアントのOAuthクライアントシークレット・認可コード・PKCE検証値を攻撃者制御のトークンエンドポイントへ送らせうると報道。修正版1.30.0。

【概要】
メンテナの勧告により、公式MCP Python SDKの影響バージョンでは、悪性MCPサーバがSDKを使うアプリを騙し、実サービスへのログインに使うOAuth資格情報（クライアントシークレット、認可コード、PKCE検証値）を攻撃者制御のトークンエンドポイントへ送らせることが可能とされる。修正はバージョン1.30.0以降。悪用は報告されていない。

【攻撃の流れ】
1. 悪性MCPサーバがトークンエンドポイントを攻撃者制御先に誘導
2. SDKがクライアントシークレット・認可コード・PKCE検証値をそこへ送信

・The Hacker News: Official MCP Python SDK Flaw Can Let Malicious Servers Steal OAuth Credentials https://thehackernews.com/2026/09/official-mcp-python-sdk-flaw-can-let.html
