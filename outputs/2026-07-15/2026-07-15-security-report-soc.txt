4. OAuth Client ID Spoofingによるステルス型Microsoft Entra ID認証情報検証キャンペーン（数百万アカウント規模）
観点: CVE関連
採用契機: ε・δ
------------------------------------------------------------

優先度: 高
対象: Microsoft Entra ID

【24時間以内の変化】
[The Hacker News 2026-07-14] Proofpointが少なくとも2つの独立した脅威アクターがOAuth Client ID Spoofing手法でMicrosoft Entra IDの窃取済み認証情報を検証していると報告

【概要】
Proofpointは、OAuth 2.0のResource Owner Password Credentials (ROPC) フローに対し登録されていない偽のOAuthクライアントIDを付与してPOSTリクエストを送ることで、成功したサインインイベントを一切生成せずにユーザー名・パスワードの正当性を検証できる手法「OAuth Client ID Spoofing」が、少なくとも2つの独立した脅威アクターにより数千テナント・最大200万超のアカウントを対象に悪用されていることを確認した。偽クライアントIDは登録アプリと紐付かないためアプリケーション名が空欄でサインインログに記録され、特定の登録アプリ名を監視対象とする既存の検知ルールをすり抜けやすい。

【推奨アクション】
・Entra IDのサインインログでアプリケーション名が空欄のROPCフロー試行を監視・アラート化する
・可能な環境ではROPCフロー自体を無効化し、より安全な認証フロー（Authorization CodeフローやPKCE等）へ移行する
・[SIEM] Entra IDサインインログ（signInLogs）でapplicationDisplayNameが空・resultTypeが特定パターンのイベントを抽出する
Splunk SPL: index=azuread sourcetype=azure:aad:signin AppDisplayName="" | stats count by UserPrincipalName, IPAddress, ResultType
→ 同一IP/UserAgentから短時間に多数のUPNに対しROPC試行が行われるパターンを特に優先確認する

【概要】
コンテナ環境の約8%で利用されるとされるメッセージブローカーRabbitMQに、アクセス制御に関する2件の脆弱性が確認された。CVE-2026-57219は管理Web APIに残存する廃止済みエンドポイントGET /api/authが未認証でブローカーの機密OAuth2設定（秘密情報含む）を開示するもので、当該秘密情報を利用する構成ではブローカーの完全な乗っ取りに直結しうる。CVE-2026-57221はパッシブなキュー・エクスチェンジ宣言操作における認可バイパスで、権限を割り当てられていないアカウントでも認証情報さえあればキュー・エクスチェンジの存在有無やメッセージ数・アクティブコンシューマ数等のメタデータを取得できる。いずれも2024年初頭から3.13.0以降のリリースラインに存在していたとされ、4.3.0/4.2.6/4.1.11/4.0.20/3.13.15で修正済み。

米財務省OFACは、ログを保持せず法執行機関に非協力を謳ってランサムウェアグループ等サイバー犯罪者へVPNサービスを提供してきた「First VPN Service (1VPNS)」の運営者Dmytro Rashevskyi、およびマルウェアをセキュリティ製品から隠蔽する「cryptor」ツールの販売者Yegeniy Vladimirovich Silayev（ベラルーシ国籍）を制裁対象に指定した。1VPNSのインフラは2026年5月に仏蘭当局とFBIボストン支局による「Operation Saffron」で摘発済みであり、本制裁はその追加措置。摘発・制裁は攻撃基盤へのリスク低減要素だが、他の同種サービスへの乗り換えによりリスクが完全に消滅するわけではない点に留意する。

【推奨アクション】
・既知の1VPNS関連インフラ・IOCへの過去の通信履歴を遡及確認する（脅威インテル部門）
・同種の匿名VPN・cryptorサービスを悪用する攻撃者の代替インフラへの乗り換えを念頭に監視を継続する
