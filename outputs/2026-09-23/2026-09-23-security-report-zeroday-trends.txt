1. CVE-2026-85102 / Check Point Quantum Security Gateway / Spark Firewall
対象: R81.20, R82, R82.10, R81.10.x, R82.00.x（VPN Site-to-Site/Remote Access使用時）※R80〜R81.10系はサポート終了
------------------------------------------------------------

優先度: 必須
CVSS: 9.8 (Critical)
状態: KEV登録済み / 実悪用確認

【24時間以内の変化】
[CISA KEV Catalog 2026-09-22] CVE-2026-85102をKEVカタログへ新規追加（catalogVersion 2026.09.22・FCEB期限2026-09-25）。既報（2026-09-10初報・実悪用未確認）から実悪用確認への状態変化
[Check Point Blog 2026-09-22] 「Security Advisory – Action Required – Active Exploitation of CVE-2026-85102」を公開し、本CVEの実悪用を公式確認

【概要】
Check Point Quantum Security GatewayおよびSpark FirewallのVPNネゴシエーション時における証明書信頼検証不備（CWE-295）で、Site-to-SiteまたはRemote Access VPNを有効化した未認証の攻撃者がGateway上で任意コードを実行できる。2026-09-09にCheck Pointが自社発見として修正版を公開した際は実悪用未確認だったが、CISAが2026-09-22付でKEVカタログへ新規追加し、Check Point公式ブログも実悪用を確認したと発表した。オランダNCSCは2026-09-12時点で悪用可能性・影響ともに「高」と評価し注意喚起していた。

攻撃の流れ:
1. 攻撃者がVPNネゴシエーション中に不正な証明書を提示し、Gatewayの証明書信頼検証不備を悪用
2. 証明書検証をバイパスして未認証のままGateway側処理に不正入力を到達させる
3. Gateway上で任意コードを実行しRCEを達成

【IoC】
IoC: 確認されず

【監視ポイント】
・Check Point Gateway/VPNログにおける異常な証明書ネゴシエーション失敗・再試行パターンと、Gatewayプロセスの予期しない子プロセス起動を監視する
Splunk SPL: index=checkpoint sourcetype=checkpoint:vpn (cert_error OR "certificate validation") | stats count by src_ip, gw_name
Splunk SPL: index=checkpoint sourcetype=checkpoint:system EventID=process_start ParentImage="*vpnd*" | stats count by ChildImage, src_ip
→ 正規のVPNクライアント証明書更新やCA入れ替え作業時の検証エラーと区別するため、失敗元IPの地理的異常・短時間の反復試行の有無を確認する

2. CVE-2026-93616 / Check Point Security Management Server / Multi-Domain Security Management / Log Server / SmartEvent
対象: Check Point Security Management Server, Multi-Domain Security Management Server, Log Server, Multi-Domain Log Server, SmartEvent（詳細版はCheck Point sk参照）
------------------------------------------------------------

優先度: 必須
CVSS: 9.8 (Critical)
状態: KEV登録済み / 実悪用確認 / ゼロデイ

【24時間以内の変化】
[The Hacker News 2026-09-22] 「Check Point Warns of Management Server Zero-Day Exploited in Targeted Attacks」を報道。少数顧客への標的型実悪用を確認
[CISA KEV Catalog 2026-09-22] CVE-2026-93616をKEVカタログへ新規追加（catalogVersion 2026.09.22・FCEB期限2026-09-25）

【概要】
Check Point Management Web Serviceにおけるディレクトリトラバーサルおよびファイルアップロードの脆弱性で、未認証の攻撃者がManagement Server上で任意スクリプトをアップロード・実行できる。事前認証不要のパストラバーサルにより任意パスのスクリプト実行・任意Javaクラスのロードが可能。Check Point Researchはゼロデイとして少数顧客への標的型実悪用を確認したと発表し、CISAが2026-09-22付でKEVカタログへ新規追加した。

攻撃の流れ:
1. 未認証の攻撃者がManagement Web Serviceへディレクトリトラバーサルを含むリクエストを送信
2. 任意パスへのスクリプトアップロードと任意Javaクラスのロードに成功
3. アップロードしたスクリプトを実行しManagement Server上でコード実行を達成

【IoC】
IoC: 確認されず

【監視ポイント】
・Management Server上のWebサービスアクセスログにおけるパストラバーサルパターン（../等）とWebルート外への予期しないファイル書き込みを監視する
Splunk SPL: index=checkpoint sourcetype=checkpoint:mgmt_web (uri_path="*../*" OR uri_path="*%2e%2e*") | stats count by src_ip, uri_path
Splunk SPL: index=checkpoint sourcetype=checkpoint:filesystem action=file_create file_path="*webroot*" NOT file_path="*expected_upload_dir*"
→ SmartConsoleのTrusted Clients設定でManagement Serverアクセスを制限しているかを併せて確認し、許可外送信元からのアクセス試行を優先的に精査する

3. CVE-2026-93952 / VeloCloud Orchestrator (VCO) on-prem
対象: VCO on-prem 6.1系・7.0系（証明書ベースでEdgeを認証する構成が対象）。5.2系・6.4系は修正版提供済み。Hosted/Dedicated版は対応済み
------------------------------------------------------------

優先度: 必須
CVSS: 10.0 (Critical)
状態: KEV登録済み / 実悪用確認 / ゼロデイ

【24時間以内の変化】
[BleepingComputer 2026-09-22] 「Arista patches VeloCloud Orchestrator zero-day exploited in attacks」を報道。証明書ベースでEdgeを認証する構成のオンプレVCOが標的
[The Hacker News 2026-09-22] CVSS 10.0のVCO脆弱性が証明書ベース構成で実悪用中と報道
[CISA KEV Catalog 2026-09-22] CVE-2026-93952をKEVカタログへ新規追加（catalogVersion 2026.09.22・FCEB期限2026-09-25）

【概要】
オンプレミス版VeloCloud Orchestrator（VCO）における不適切な入力検証の脆弱性で、ログイン不要の遠隔攻撃者が特権的な内部機能へアクセスしVCOホストの機密性・完全性・可用性を侵害できる。証明書ベースでEdgeを認証する構成のみが影響を受け、攻撃者はWebインターフェースへのネットワークアクセスとEdgeの認証用証明書公開部分の入手が必要となる。Aristaは外部からの指摘で発見し、実悪用中であることを確認したと発表。CVSS 10.0（最大値）でCISAが2026-09-22付KEVへ新規追加した。

攻撃の流れ:
1. 攻撃者が対象EdgeのTLS証明書公開部分を入手しVCO Web管理インターフェースへアクセス
2. 不適切な入力検証を悪用し特権的な内部機能を未認証で呼び出す
3. VCOホストの設定・データを改ざん、または制御を奪取

【IoC】
IoC: 確認されず

【監視ポイント】
・VCO管理コンソールへの証明書ベース認証試行ログと、内部特権APIへの未認証アクセス試行を監視する
Splunk SPL: index=arista_vco sourcetype=vco:access uri_path="*internal*" status!=401 | stats count by src_ip, uri_path
Splunk SPL: index=arista_vco sourcetype=vco:auth auth_method=cert | stats count by src_ip, edge_id | where count > 20
→ 証明書ベースEdge認証を使用していない環境は本脆弱性の影響を受けないため、まず自組織の認証方式（証明書 vs パスワード）を確認したうえで監視要否を判断する

4. CVE-2026-94127 / BIG-IP APM
対象: BIG-IP APM 21.1.0系, 17.5.x系, 17.1.x系（該当エンジニアリングホットフィックス未適用でAPMアクセスポリシー＋OAuthプロファイルを仮想サーバに構成している場合）
------------------------------------------------------------

優先度: 必須
CVSS: 9.8 (Critical)
状態: KEV登録済み / 実悪用確認

【24時間以内の変化】
[F5 PSIRT (K000162605) 2026-09-23] BIG-IP APMのOAuthプロファイル関連ヒープバッファオーバーフローについて実悪用を確認しエンジニアリングホットフィックスを公開
[CISA KEV Catalog 2026-09-22] CVE-2026-94127をKEVカタログへ新規追加（catalogVersion 2026.09.22・FCEB期限2026-09-25）

【概要】
BIG-IP APMのアクセスポリシーとOAuthプロファイルを仮想サーバに構成している場合、特定の悪意あるトラフィックによりヒープベースのバッファオーバーフローが発生し、未認証の遠隔攻撃者によるリモートコード実行（RCE）が可能となる。データプレーンの問題でありコントロールプレーンへの露出はない。F5がAppliance modeでも脆弱と明記した上で実悪用を確認し、CISAが2026-09-22付でKEVカタログへ新規追加した。恒久修正までのつなぎとしてF5提供のiRuleによる一時緩和策がある。

攻撃の流れ:
1. 攻撃者がAPM＋OAuthプロファイルを構成した仮想サーバへ細工したOAuth関連トラフィックを送信
2. リクエスト処理中にヒープメモリが破損（バッファオーバーフロー）
3. 未認証のままBIG-IPデータプレーン上でリモートコード実行を達成

【IoC】
IoC: 確認されず

【監視ポイント】
・BIG-IP APMのOAuth関連トラフィック処理での異常終了・再起動ログと、想定外に大きいOAuthリクエストペイロードを監視する
Splunk SPL: index=f5_bigip sourcetype=f5:bigip:apm (restart OR core_dump OR tmm_panic) | stats count by hostname
Splunk SPL: index=f5_bigip sourcetype=f5:bigip:ltm virtual_server=* protocol=oauth | eval body_len=len(http_body) | where body_len > 8192
→ 恒久パッチ未適用の場合はF5提供iRuleの適用有無を優先確認し、tmmプロセスの予期しないクラッシュ・再起動を実悪用の先行シグナルとして扱う

1. Red Heron（GreyNoise追跡名: Operation Kapibala・Chinese-speaking・帰属信頼度: 中）（別名: Kapibala / 国家帰属: 不明 / 帰属信頼度: medium）

【24時間以内の変化】
[GreyNoise 2026-09-21] Global Observation Grid（GOG）センサー網でChinese-speakingとみられる単一の攻撃者による2026-05-07以降の活動を確認し、Acronisが以前報告した『Red Heron』クラスタと同一C2ドメイン・マルウェアファミリー・TTPを共有すると結論・作戦名『Kapibala』としてブログ公開
[BleepingComputer / SecurityWeek / Help Net Security 2026-09-22] GreyNoise調査を引用し実被害規模（WordPress wp2shell経由で49組織・29カ国、ZyXEL GS1900経由で996台・48カ国、西側政府機関から18,566件超の平文パスワード・PII窃取）を報道・窓内で広範な媒体追随を確認

【概要】
GreyNoiseのGlobal Observation GridがChinese語話者と推定される単一の攻撃者（国家帰属の言及なし）による大規模な脆弱性悪用キャンペーン『Operation Kapibala』を検出し、既知の『Red Heron』クラスタ（Acronis報告・Gitea CVE-2026-60004悪用等で既知）と同一のC2ドメイン・マルウェアファミリー・TTPを共有すると中程度の確度で関連付けた（推測—Chinese語話者の痕跡およびUTC+8圏での活動時間帯という技術的手掛かりに基づく分析であり、政府機関による公式な国家帰属は行われていない）。WordPress Core『wp2shell』脆弱性（CVE-2026-63030・CVE-2026-60137）を2026-07-20頃から悪用し29カ国49組織（主に小規模事業者・政府機関）を侵害、うち西側政府機関1件では17件のAMSIバイパススクリプトを実行し権限昇格・レジストリ抽出を経てバックエンドSQLデータベースから法執行機関関連の平文パスワード・個人情報を含む18,566件超のレコードを窃取した。並行してZyXEL GS1900スマートマネージドスイッチの高深刻度脆弱性CVE-2026-7273（2026-08-17から悪用開始・本脆弱性の実悪用として世界初の公開文書化）を突き48カ国996台（イタリア133・米国129・台湾123・フランス90・韓国69台等）を侵害し、うち564台は工場出荷時デフォルト認証情報のまま稼働していたためデバイス設定・ネットワーク情報・ハッシュ化されたroot権限認証情報を窃取した。同一攻撃者はUbiquiti UniFi OS（CVE-2026-34908/34909/34910）・FlowiseAI（CVE-2026-56271）・Gitea（CVE-2026-60004）・Nuclio（CVE-2026-79756）・SENAITE LIMS（CVE-2026-54569）・Proxmox VE（CVE-2023-54391）・Linux Dirty Pipe（CVE-2022-0847）等、多岐にわたる技術スタックへの脆弱性武器化も並行して観測されている。

攻撃の流れ（判明分）:
1. WordPress『wp2shell』の脆弱性連鎖（CVE-2026-63030・CVE-2026-60137）またはZyXEL GS1900のCVE-2026-7273・工場出荷時デフォルト認証情報を悪用し初期アクセスを獲得
2. 侵害環境内でAMSIバイパススクリプトの多重実行・権限昇格・レジストリ抽出等の偵察/横展開を実施し、kapibala/kapibala2等のアカウントを作成
3. バックエンドSQLデータベースまたはデバイス設定情報へアクセスし、平文パスワード・PII・ハッシュ化認証情報を窃取してC2（p3.981666.xyz等）へ持出
