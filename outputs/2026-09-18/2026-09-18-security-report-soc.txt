1. IBM Guardium Data Security Centerに同梱サードパーティ由来の脆弱性251件（CVSS10.0含む）
観点: CVE関連
採用契機: η
------------------------------------------------------------

優先度: high
対象: IBM Guardium Data Security Center（3.8.11未満）

【24時間以内の変化】
[Security NEXT 2026-09-17] 「IBM Guardium Data Security Center」に脆弱性 - 早急に更新をと報道。バンドルされたサードパーティコンポーネント（Netty, Jackson Databind等）起因で計251件のCVEが一括公表され修正版3.8.11がリリースされた

【概要】
IBM Guardiumはデータベース/データセキュリティ監視製品であり、SOCのデータアクセス監査・異常検知基盤として運用されるケースが多い。今回の一括パッチにはNetty由来のDNSキャッシュポイズニング系脆弱性（CVE-2026-47691, CVE-2026-45674、いずれもCVSS基本値10.0）や、Jackson Databindのデシリアライズ制限バイパス（CVE-2026-54513, CVE-2026-54512、CVSS8.1）に加え、HTTPリクエストスマグリング・認証情報漏えい・アクセス制御バイパス・DoSに分類される脆弱性が含まれる。製品自体がセキュリティ監視基盤であるため、悪用時の影響（監視データへの不正アクセス・監視機能の無効化）が大きい。

【推奨アクション】
・Guardium Data Security Centerの稼働バージョンを確認し、3.8.11未満であれば即時パッチ適用計画を立てる
・パッチ適用までの間、Guardium管理インターフェース・APIの公開範囲を制限し、インターネットからの直接到達性を遮断する
・CVSS10.0の2件（Netty DNSキャッシュポイズニング）はネットワーク到達性のあるコンポーネントで悪用条件が緩いため、外部到達可能な環境では優先度最上位で扱う
→ 異常な設定変更・認証試行がないか確認する。

【参照】
https://www.security-next.com/190443
https://www.ibm.com/support/pages/node/7262295

2. NIST × CISAがトークン・アサーションの偽造/窃取/悪用対策プレイブックNIST IR 8587を公表
観点: ゼロデイ関連
採用契機: ζ
------------------------------------------------------------

優先度: medium
対象: 該当なし

【24時間以内の変化】
[Help Net Security 2026-09-16] NIST and CISA finalize playbook to stop token theft and forgeryと報道。NIST IR 8587としてトークン/アサーションの偽造・窃取・誤用対策プレイブックを正式公表

【概要】
本ガイダンスは、暗号鍵管理・トークン検証手順・トークンのライフサイクル管理・IdP/認可サーバ設計に関する実装指針を示すもので、対象は連邦機関・クラウドサービス事業者に限らずトークンベースのアクセス管理を行う組織全般に及ぶ。特徴的なのは、AIエージェントが人間のユーザーと同一の認証機構（トークン）でシステムにアクセスする点に触れ、AIエージェントに対しても同様のトークン保護策を適用すべきと明記している点で、SOCのログ監視設計に直接関わる。

【推奨アクション】
・トークン利用状況の収集・ログ化がSIEMで行えているか確認し、不足があれば取り込み対象に追加する
・侵害されたトークン/署名鍵への対応手順（失効・ローテーション）が既存のIRプレイブックに明記されているか確認する
・AIエージェントが利用するサービスアカウント/トークンを人間ユーザーと同列に監視対象へ含める
→ 次回のIR/監視設計レビューサイクルまでに反映する。

【参照】
https://www.helpnetsecurity.com/2026/09/16/nist-cisa-cloud-token-security-guidance/

3. @cosme（アイスタイル）でファイル転送サービスの設定ミスによりメールアドレス等約1.1万件が漏えいの可能性
観点: ゼロデイ関連
採用契機: β
------------------------------------------------------------

優先度: low
対象: @cosme（アットコスメ）

【24時間以内の変化】
[ITmedia NEWS 2026-09-17] 「@cosme、ユーザー1万人超のメアド漏えいの可能性 ファイル転送サービスの設定ミスで」と報道

【概要】
従業員が個人情報を含むファイルを外部ファイル転送サービスで受け渡した際に公開設定を誤り、約20分間（9/2 14:20頃〜）URLを知っていれば誰でもアクセス可能な状態になっていたと公表された。漏えいの可能性がある情報はメールアドレス・メールマガジン配信設定・会員登録時発番のユーザーIDの3項目で、氏名・住所・パスワード・クレジットカード情報は含まれない。規模・機微度ともに小さいが、外部ファイル転送サービスの公開設定ミスという典型的な人的ミス起点のインシデントであり、SOCとして自組織の同種運用の再確認材料になる。

【推奨アクション】
・自組織で外部ファイル転送サービスを業務利用している場合、公開設定のデフォルトが「限定公開」になっているか確認する
・個人情報を含むファイル送受信の承認フロー（ダブルチェック）の有無を確認する

【参照】
https://www.itmedia.co.jp/news/article/2609/17/2000001572/
