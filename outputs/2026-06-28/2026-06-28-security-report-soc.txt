【概要】
Ciscoが2026年7月1日リリース予定の重要セキュリティアップデートを事前通知した。対象はCisco IOS XE、NX-OS、ASA、FTDを含む主要ネットワーク・セキュリティ製品群。具体的なCVE番号はリリース前のため未公開だが、事前通知の慣行から少なくとも1件以上のCritical/High級脆弱性が含まれると予測される。SOCとして7月1日のリリースと同時に適用判断ができるよう、変更管理手続きの事前確認と緊急パッチ適用体制の準備が推奨される。

・重要度に応じた72時間以内のパッチ適用基準を事前確認

2. デバイスコードフィッシング急増（H1 2026比1380%増）: Tycoon2FA等18キットの検知強化
観点: ゼロデイ関連
採用契機: ε・δ・β
------------------------------------------------------------

優先度: 中
対象: Microsoft 365 / Azure AD / OAuth 2.0

【24時間以内の変化】
[Help Net Security / Infosecurity Magazine 2026-06-27] H1 2026のデバイスコードフィッシングが前年比1380%増。Tycoon2FA・EvilTokens・Kali365・Ghost Hub・Cyb3rの5グループ主導で18キットが確認された

【概要】
デバイスコード認証フロー（OAuth 2.0 Device Authorization Grant）を悪用したMFA回避フィッシングが2026年上半期に急増し、前年比1380%増が報告された。Tycoon2FA・EvilTokens・Kali365・Ghost Hub・Cyb3rの5グループが主導し、18種類のフィッシングキットが確認されている。攻撃者はデバイスコード要求をトリガーし、生成されたuser_codeを標的に入力させることでアクセストークンを窃取。MFAを有効にしていても迂回可能なため、Conditional Access PolicyによるDevice Code Flowの制限が有効な対策となる。

【推奨アクション】
・Azure AD Conditional Access PolicyでDevice Code Flowを制限（user_code認証を社内IPまたはCompliant Device限定に設定）
・SIEM/SentinelでのDevice Code認証イベント（sign-in-logs: deviceCode）の監視アラート設定
・セキュリティ意識向上トレーニングへのデバイスコードフィッシング事例の追加
・不審なuser_codeの入力を求めるメッセージへの対応手順のインシデントレスポンスプレイブック更新
Splunk SPL: index=azure_ad sourcetype=azure:aad:signin authenticationProtocol=deviceCode | stats count by UserPrincipalName, IPAddress, ResultType | where ResultType=0 | sort -count
→ deviceCode認証の成功（ResultType=0）を通常業務外の時間帯・IPから検出した場合はトークン窃取の可能性。Tycoon2FA等のキットは短時間に集中して試行するため突発的なcount増加も要注意

https://helpnetsecurity.com/2026/06/27/device-code-phishing-surge-2026/
https://www.infosecurity-magazine.com/news/device-code-phishing-1380-percent-2026/
