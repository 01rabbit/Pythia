1. Dell ThinOS 10: 未認証コマンドインジェクション/RCE4件（CVE-2026-81467/81048/81046/81468）
観点: CVE関連 / 採用契機: β
------------------------------------------------------------

優先度: 高
対象: Dell ThinOS 10（シンクライアントOS、2605_10.2616未満）

【24時間以内の変化】
[Dell PSIRT 2026-09-11] Dell ThinOS 10に未認証コマンドインジェクション/RCE等4件（CVSS 9.1〜9.8）を公開、2605_10.2616で修正

【概要】
官公庁・金融機関のVDI環境で広く使われるDellのシンクライアント専用OS「ThinOS 10」に、未認証の遠隔攻撃者によるコマンド実行を許す脆弱性が複数公開された。CVE-2026-81467（CVSS 9.8・遠隔からのOSコマンドインジェクション）・CVE-2026-81046（CVSS 9.4・保護機構不全による任意コード実行）は未認証・遠隔から悪用可能、CVE-2026-81048（CVSS 9.6）は隣接ネットワークからのコマンドインジェクション、CVE-2026-81468（CVSS 9.1）は高権限攻撃者を前提とする。config.yml のスコープ（finance/government/critical_infrastructure）に直接該当するため、優先度高としてSOCに提示する。

【推奨アクション】
・Dell ThinOS 10を利用する端末を棚卸しし、2605_10.2616未満のバージョンを特定する
・ファームウェア更新（2605_10.2616以降）を最優先で適用する
・更新までの間、シンクライアント管理ネットワークをVLAN分離しインターネット直接露出を避ける
Splunk SPL: index=network dest_port IN (443,4433) app=wyse_mgmt | stats count by src_ip dest_ip
→ 管理コンソール外からのThinOS管理ポートへのアクセスは要確認

【参照】
https://www.dell.com/support/kbdoc/

2. GeoVision GV-LPC2211（ONVIFネットワークカメラ）: 認証欠如・リプレイ攻撃2件
観点: CVE関連 / 採用契機: β/η
------------------------------------------------------------

優先度: 中
対象: GeoVision GV-LPC2211 V1.13

【24時間以内の変化】
[NVD 2026-09-11] GeoVision GV-LPC2211にWS-SecurityリプレイによるONVIF操作偽装(CVE-2026-88278)と未認証PTZ制御(CVE-2026-88285)を公開

【概要】
監視カメラ大手GeoVisionのGV-LPC2211（V1.13）で、WS-SecurityのUsernameTokenの鮮度・nonce再利用対策が欠如しておりPasswordDigestトークンをリプレイしてONVIF操作を偽装できる（CVE-2026-88278・CVSS 9.8）、およびPTZ制御サービスが認証なくネットワーク到達可能で任意のPTZ/シリアルコマンドを実行できる（CVE-2026-88285・CVSS 9.4）の2件が公開された。国内でも監視カメラは工場・小売店舗等で広く利用されるため、ネットワーク露出状況の確認を推奨する。

【推奨アクション】
・GV-LPC2211のファームウェア更新有無をGeoVisionへ確認する
・ONVIF/PTZ管理ポートをVLAN分離しインターネットから遮断する
・カメラ管理ネットワークへのアクセスログを確認し、想定外のPTZ操作がないか確認する
Splunk SPL: index=network dest_port IN (80,8080,554) app=onvif | stats count by src_ip dest_ip
→ 管理端末以外からのPTZ操作コマンドは要調査

【参照】
https://euvd.enisa.europa.eu/vulnerability/EUVD-2026-75312

3. Renovate: コンテナレジストリのLinkヘッダー追従によるクレデンシャル漏洩4件
観点: CVE関連 / 採用契機: γ
------------------------------------------------------------

優先度: 中
対象: Renovate（依存関係自動更新ツール）44.11.3未満/44.11.2未満

【24時間以内の変化】
[GitHub Security Advisories 2026-09-11] Renovateのページネーション追従・タグ列挙処理に伴うクレデンシャル漏洩4件(CVE-2026-88880・CVE-2026-88881・CVE-2026-88882・CVE-2026-88887)を公開

【概要】
CI/CDで広く使われる依存関係自動更新ツールRenovateにおいて、GitLab/GitHubサーバが返すHTTP LinkヘッダーのページネーションURLやコンテナレジストリのタグ/ダイジェスト列挙時のリダイレクト先へ、資格情報を検証なく付与して追従してしまう不備が4件公開された。CVE-2026-88880はGitLabサーバページネーション追従時のLinkヘッダー宛先未検証、CVE-2026-88881はGitHubサーバが供給するページネーションリンクへの追従、CVE-2026-88882はコンテナイメージのタグ/ダイジェスト列挙時のLinkヘッダー追従、CVE-2026-88887はコンテナレジストリのタグ/ダイジェスト列挙時の同種の資格情報付与（いずれもCVSS 9.2）。悪意あるレジストリ/Gitサーバを経由してCI上のトークンを窃取される供給網リスクがある。44.11.3（GitLab関連）/44.11.2（コンテナレジストリ関連）で修正済み。

【推奨アクション】
・自組織のRenovate導入バージョンを確認し44.11.3以降へ更新する
・Renovateに付与しているトークンのスコープを必要最小限に見直す
・CI実行ログでRenovateから外部未知ホストへのリダイレクト追従がないか確認する
Splunk SPL: index=ci_cd sourcetype=renovate_log "redirect" | stats count by dest_host
→ 既知の正規レジストリ/Gitホスト以外へのリダイレクト追従は要確認

【参照】
https://cve.imfht.com/intel/776940

4. Apache Camel K: テナント制御CR経由のコード実行・不正リソース作成2件
観点: CVE関連 / 採用契機: β/γ
------------------------------------------------------------

優先度: 中
対象: Apache Camel K（Kubernetesオペレータ）2.0.0〜2.9.2 / 2.10.0〜2.10.1

【24時間以内の変化】
[Apache Software Foundation 2026-09-11] Apache Camel Kのカスタムリソース経由のコード実行・YAMLインジェクション2件(CVE-2026-80351/80352)を公開、2.9.3/2.10.2/2.11.0で修正

【概要】
Kubernetes上でApache Camelの統合パイプラインを運用するApache Camel Kにおいて、テナントが制御可能なMaven設定・カスタムリソース(CR)を経由し、CR作成権限を持つ攻撃者がオペレータPodの権限でコード実行（CVE-2026-80351）や不正なKubernetesオブジェクト作成（CVE-2026-80352）を行える不備が公開された（いずれもCVSS 9.8、悪用にはCR作成権限が前提）。マルチテナントKubernetesクラスタでCamel Kを運用する場合はテナント分離の観点で影響がある。

【推奨アクション】
・Apache Camel Kを2.9.3/2.10.2/2.11.0以降へ更新する
・マルチテナント環境ではCamel K用CRのRBAC権限を最小権限で再確認する
・オペレータPodの実行権限（クラスタ内の到達範囲）を必要最小限に制限する
Splunk SPL: index=k8s_audit verb=create resource=customresourcedefinition user=*camel-k* | stats count by user resource
→ テナントユーザーからのCR経由の異常なAPI呼び出しは要確認

【参照】
https://camel.apache.org/security/
