・CVE-2023-49105 / ownCloud core（WebDAV API）
CVSS: 9.8
ownCloud core のWebDAV APIにおいて、ユーザーの署名鍵（signing-key）が未設定の場合でも事前署名URL（pre-signed URL）が有効なものとして受理されてしまう認証バイパスの脆弱性。ユーザー名が既知であれば未認証の攻撃者が任意のファイルへアクセス・改変・削除できる。2023年11月の開示直後からPoCエクスプロイト（ambionics/owncloud-exploits）が公開されており継続的にスキャン・悪用の対象となってきたが、CISAが2026-08-27付で改めてKEVカタログへ追加したことで、パッチ未適用インスタンスへの実悪用が現在も継続していることが示唆される。
IoC: 確認されず

監視: ownCloud WebDAV APIへの署名パラメータ欠落・不正な事前署名URLリクエストを監視する
Splunk SPL: index=web_proxy sourcetype=access_combined uri_path="*/remote.php/dav/*" OR uri_path="*/remote.php/webdav/*" | search NOT uri_query="*OC-Signature=*" | stats count by clientip, uri_path
→ 署名パラメータ(OC-Signature等)を伴わない/remote.php/webdav配下への大量リクエストは事前署名URL悪用試行の可能性。正規クライアントの初回同期トラフィックとの誤検知に注意

参照: https://www.cisa.gov/known-exploited-vulnerabilities-catalog; https://www.greynoise.io/blog/cve-2023-49105-webdav-api-authentication-bypass-in-owncloud; https://github.com/ambionics/owncloud-exploits

・CVE-2026-53362 / Linux Kernel（ipv6 __ip6_append_data / フラグメントギャップ会計処理）
CVSS: 7.8
__ip6_append_data() のpaged-allocation分岐（MSG_MORE / NETIF_F_SG / 大きなfraglen条件）でalloclen・pagedlenの算出にfraggapが正しく反映されず、UDPv6ソケット経由でヒープ破壊を引き起こせる脆弱性。Red Hatはこれを「ipv6_frag_escape」（RHSB-2026-009）としてコンテナエスケープの文脈で扱っており、コンテナ内の非特権ユーザーがホストへエスケープしSELinuxの強制アクセス制御を回避してroot権限を取得しうると警告している。CISAのKEV登録は実悪用の証拠があることを示すが、独立した第三者による攻撃観測の報道は本日時点で確認できていない。
IoC: 確認されず

監視: コンテナ内からの異常な特権昇格・ホストプロセスとしての予期しないroot権限取得を監視する
Splunk SPL: index=linux_audit sourcetype=auditd type=SYSCALL syscall=setuid OR syscall=setns | stats count by hostname, exe, container_id
→ コンテナランタイム（Falco等）のカーネルイベント監視と組み合わせ、コンテナ名前空間外への予期しないアクセスを重点的に確認する。SELinux監査ログのAVC denyバイパスにも注意

参照: https://access.redhat.com/security/vulnerabilities/RHSB-2026-009; https://ubuntu.com/security/CVE-2026-53362

・CVE-2026-81934 / Redis Server（TLS構成時のtlsProcessPendingData処理）
CVSS: 9.8
RedisをTLS構成で稼働させている場合、tlsProcessPendingData()が管理するTLS保留データリストの反復処理に、ネストされたイベントループ処理中のノード削除に対する保護が欠けている。接続がコマンド実行中に切断されると、そのリストノードは解放されるが、外側のループが解放済みノードへの参照を保持し続けるためUse-After-Freeが発生する。未認証のリモート攻撃者がこれを悪用し、redis-serverプロセスの権限で任意のコマンドを実行できる。研究者グループv12-securityはLuaオブジェクトのアドレスリーク・保留リスト内の接続順序操作・解放済みノードの再利用による1ビット書き込みプリミティブ化・Luaテーブルの再構築による読み書きプリミティブ確立・バイナリのメモリレイアウト特定・再起動機構の悪用という7段階のエクスプロイトチェーンをPoCとして公開している。影響を受けるのはRedis 8.8.0でTLSを有効化した構成であり、8.2.9/8.4.6/8.6.6/8.8.2/8.10.1で修正済み。本日時点で在野での実悪用の確認報道はない。
IoC: 確認されず

監視: TLS有効化したRedisインスタンスへの異常な接続パターン・予期しないRedisプロセス再起動を監視する
Splunk SPL: index=redis_logs sourcetype=redis_server ("Ready to accept connections" OR "Server initialized") | transaction host maxspan=5m | where eventcount > 3
Splunk SPL: index=network_traffic dest_port=6379 OR dest_port=6380 | stats count dc(src_ip) as unique_sources by dest_ip | where unique_sources > 20
→ 短時間での繰り返しRedis再起動ログはUAFエクスプロイトの試行失敗（クラッシュ）の兆候である可能性がある。TLSポートへの接続元多様性の急増にも注意

参照: https://github.com/redis/redis/commit/6d088c335d5c3ec49a6c28486140b498e70b7834; https://www.thehackerwire.com/redis-use-after-free-rce-in-tls-handling-cve-2026-81934/; https://github.com/v12-security/pocs/tree/main/redis/server_ssl
